# 启动参数与运行指南

日期：2026-10-06（并发改造完成之后）。本文只讲**怎么启动、有哪些参数、怎么读结果**。
执行模型与逐步骤的并发边界见 `eval/主路线实现细则.md` §一～§三；待办见 `eval/待优化清单.md`。

---

## 0. 前置条件

| 项 | 说明 |
|---|---|
| 解释器 | 本机是 `D:\python\python.exe`（**不是** conda，也不是 venv）。换机器按实际路径替换 |
| 模块路径 | `ict` 没有 `pip install` 过，所以**每条命令都要 `$env:PYTHONPATH = "src"`** |
| GPU 解析服务 | 服务器上 `bash /root/deploy/start_vllm.sh && bash /root/deploy/start_parse.sh` |
| 隧道 | 另开一个窗口 `D:\python\python.exe deploy\tunnel.py`，**整个过程别关** |
| 自检 | `curl.exe -s http://127.0.0.1:6008/health` 必须含 `"ok":true` |
| 品目目录 | `data/procurement_catalog_2022.json`（1 MB）**必须在**。它在 `.gitignore` 里，换机器要单独带；缺它 `Catalog()` 会让每则公告在开头直接崩 |

## 1. 三种启动方式

```powershell
cd <repo>
$env:PYTHONPATH = "src"

# ① 单则（不带公告级并发，步骤内并发照常生效）
D:\python\python.exe -m ict.cli run t20260202_26140146

# ② 批量（公告级并发）
D:\python\python.exe -m ict.cli batch t20260202_26140146 t20260512_26551404 --workers 2

# ③ 带打分与诊断（测性能、看回归用这个，信息最全）
D:\python\python.exe eval\run_e2e.py t20260202_26140146 t20260512_26551404 --workers 2
```

`--workers` 覆盖 `ICT_ANNOUNCEMENT_WORKERS`，命令行优先。**`--workers 1` 与并发改造前的串行路径
逐字节等价**（已被回放验证），想先排除并发因素就跑这个。

`ict-run` 这个命令用不了——包没装成 console script。用 `-m ict.cli`。

## 2. 参数总表

在**启动 python 之前**设好（`$env:XXX = "值"`）。

> 闸门与线程池在 `import` 时创建，所以**进程内改环境变量对它们无效**。当前 PowerShell 会话里的值会一直
> 保留到关掉窗口，**换一组实验必须显式重设**，否则上一组的值会带进来。

### 2.1 并发（2026-10-06 新增）

| 参数 | 默认 | 作用 | 备注 |
|---|---|---|---|
| `ICT_ANNOUNCEMENT_WORKERS` | `2` | 同时在途的公告数 | 受内存限制：每则在途公告都握着自己的解析结果。2 核 4G 上建议 2～4 |
| `ICT_LLM_MAX_CONCURRENCY` | `8` | 全局在飞的模型调用数（同时决定 `LLM_POOL` 线程数） | 设 1 = 完全串行，用来做对照 |
| `ICT_LOCAL_HEAVY_WORKERS` | `2` | 本机 CPU 重活的并发数：页画像、缩略图、docx/xlsx 读取 | 跟着核数走 |
| `ICT_PARSE_MAX_INFLIGHT` | `1` | **同一时间在 GPU 上解析的文档数** | 1 是契约值。调大属于实验 |
| `ICT_LLM_RETRY_ATTEMPTS` | `3` | 429/5xx/网络错误的尝试次数（含首次） | |
| `ICT_LLM_RETRY_WAIT` | `1` | 重试退避基数（秒，指数 + 抖动） | 设 `0` = 立即重试 |

### 2.2 端点与超时

| 参数 | 默认 | 说明 |
|---|---|---|
| `ICT_LLM_BASE_URL` | `https://api.deepseek.com` | |
| `ICT_LLM_API_KEY`（或 `DEEPSEEK_API_KEY`） | 空 | 缺失时第 1 步直接 `llm_call_failed`，整则 `failed` |
| `ICT_LLM_MODEL` | `deepseek-flash` | |
| `ICT_LLM_TIMEOUT` | `180` | 读超时 |
| `ICT_LLM_CONNECT_TIMEOUT` | `15` | **新增**：连不上就快点失败 |
| `ICT_PARSE_URL` | `http://127.0.0.1:6008` | 隧道地址 |
| `ICT_PARSE_TOKEN` | 空 | 服务端设了 token 才需要 |
| `ICT_PARSE_TIMEOUT` | `600` | **一份文档**解析多久算超时 |
| `ICT_PARSE_CONNECT_TIMEOUT` | `10` | **新增**：不可达时 10 秒失败，而不是按 600 秒卡住队列里的每个文件 |
| `ICT_PARSE_RUN_WORKERS` | `3` | ⚠️ **已失效**：它只喂给 `parse_runs`，而主流程从不调用那个方法。改了没有任何效果 |

### 2.3 只影响离线回放（**只能来自进程环境变量，写进 `.env` 不生效**）

| 参数 | 默认 | 说明 |
|---|---|---|
| `ICT_LLM_MODE` | `live` | `live` / `record` / `replay` |
| `ICT_CASSETTE` | `work/cassettes/llm.jsonl` | 回放表路径 |
| `ICT_REPLAY_LATENCY_MS` | `0` | 给回放假装延迟，用来离线量并发收益 |

这三个被 `config.ENV_FILE_EXCLUDED` 明确排除在 `.env` 之外：它们属于测试挡板，一行残留会让所有模型
答案变成回放。**其余参数都可以写进 `.env`**（`load_local_env()` 用 `setdefault`，所以进程环境变量优先）。

### 2.4 不受环境变量控制的固定值（在 `src/ict/config.py`，改动需走规则区流程）

`PARSE_MAX_PAGES_PER_FILE=40`、`PARSE_RUN_PAGES=12`（第 6 步每次送页数）、`MAX_PAGES_PER_FILE=30`、
`MAX_PAGES_PER_ANNOUNCEMENT=100`、`PAGE_LOCATE_LIMIT=80`、`PAGE_CONTEXT_CHARS=6000`、
`PAGE_CONTEXT_TABLES=6`、`MERGE_THINKING=True`。

### 2.5 附件解包（与主流程分开的预备步骤）

```powershell
D:\python\python.exe prep\extract_attachments.py --workers 6
```

## 3. 推荐配置

```powershell
cd <repo>
$env:PYTHONPATH  = "src"

# 并发
$env:ICT_ANNOUNCEMENT_WORKERS  = "2"     # 同时在途公告数
$env:ICT_LLM_MAX_CONCURRENCY   = "8"     # 模型调用在飞数
$env:ICT_LOCAL_HEAVY_WORKERS   = "2"     # 本机 CPU 重活
$env:ICT_PARSE_MAX_INFLIGHT    = "1"     # GPU 单文档（契约值）

# 超时
$env:ICT_PARSE_CONNECT_TIMEOUT = "10"
$env:ICT_LLM_CONNECT_TIMEOUT   = "15"

# 确认不在回放模式
$env:ICT_LLM_MODE = $null

# 跑
D:\python\python.exe eval\run_e2e.py <你的 ids> --workers 2
```

## 4. 结果怎么读

```
status=success wall=12.3s counts={...}
llm_calls={'understand_announcement': 1, ...}
failures=[]
batch wall=43.7s cpu=2.7s (workers=2)
```

| 看什么 | 含义 |
|---|---|
| `batch wall` / `cpu` | **两个数一起看**。墙钟大、CPU 小 = 瓶颈在网络/GPU，不在本机 CPU。这个管线本地 CPU 是亚秒级 |
| 每则 `wall=` | 就是 `10_run_report.json` 的 `duration_ms` |
| `failures` | 服务器在线时**不该出现** `parse_unreachable` / `parse_http_failed`；出现说明隧道或服务没通 |
| `counts.parsed_pages` | 服务器在线时应大于 0，且 `06_page_decisions.json`、`07_attachment_extraction.json` 应有内容 |
| 每则 `wall` 的**分布** | 队列轮转的效果体现在"分布更均匀"，不是"总量更快"（见 `实现细则` §2.1） |

## 5. 可选实验（每组只改一个变量）

### 5.1 在途公告数（服务器不用动）

```powershell
$env:ICT_PARSE_MAX_INFLIGHT = "1"
D:\python\python.exe eval\run_e2e.py @ids --workers 2 2>&1 | Select-String "status=|batch wall"
$env:ICT_PARSE_MAX_INFLIGHT = "1"
D:\python\python.exe eval\run_e2e.py @ids --workers 4 2>&1 | Select-String "status=|batch wall"
$env:ICT_PARSE_MAX_INFLIGHT = "1"
D:\python\python.exe eval\run_e2e.py @ids --workers 8 2>&1 | Select-String "status=|batch wall"
```

验证的是：worker 全部卡在 4c 等解析时，后面的公告根本没开始跑，模型端点因此空转。

### 5.2 GPU 并发（前提：服务端能同时收两个请求）

```powershell
$env:ICT_PARSE_MAX_INFLIGHT = "2"
D:\python\python.exe eval\run_e2e.py @ids --workers 4 2>&1 | Select-String "status=|batch wall"
$env:ICT_PARSE_MAX_INFLIGHT = "2"
D:\python\python.exe eval\run_e2e.py @ids --workers 8 2>&1 | Select-String "status=|batch wall"
```

**做之前必须先确认服务端能并发**：`/parse` 是 `async def` 但内部跑同步阻塞体，单个 uvicorn worker
同一时刻只处理一个请求，那样子设 2 也没有意义（只是在服务端门口排队）。
给解析服务加 worker 要谨慎：**每个 uvicorn worker 会各自加载一份 PaddleOCR-VL 管线**，显存和内存都会翻倍。

依据：单文档逐页串行实测 4.45 秒/页（≈0.22 页/秒），而页级并发 16 时约 3 页/秒——单文档很可能喂不满 GPU 引擎。

### 5.3 记录表

| 组 | MAX_INFLIGHT | workers | batch wall | batch cpu | 峰值内存 | GPU 页/秒 |
|---|---|---|---|---|---|---|
| A1 | 1 | 2 | | | | |
| A2 | 1 | 4 | | | | |
| A3 | 1 | 8 | | | | |
| B1 | 2 | 4 | | | | |
| B2 | 2 | 8 | | | | |

峰值内存：Linux 用 `/usr/bin/time -v`（看 `Maximum resident set size`）；Windows 看任务管理器里 python.exe 的内存列。

## 6. 回归验收（不花钱）

```powershell
$env:ICT_LLM_MODE = "replay"
D:\python\python.exe eval\run_replay.py replay <ids> --out work\_check\after --workers 2
D:\python\python.exe eval\run_replay.py diff work\_stage0_baseline\replay1 work\_check\after
```

必须输出 `结果：一致`。有 `CassetteMiss` 就是在报"某一步的输入变了"。

**注意**：回放覆盖不到 4c／5／6 三步（录制时解析服务未启动），所以**解析队列的顺序改动无法靠回放验证**——
那部分靠 `tests/test_parse_queue.py` 的离线单测和线上实测。

## 7. 六个坑

1. **参数在 `import` 时读一次**：闸门与线程池是模块级对象，进程内改环境变量无效；换组实验要显式重设。
2. **别用回放测性能**：回放里没有网络等待、没有解析，只剩亚秒级本地 CPU，什么都测不出来。
3. **服务端 `uvicorn --workers 1`**：多 worker 会让进程内的单文档解析队列失效，变成 N 份文档同时压 GPU。
4. **`.env` 里不要写 `ICT_LLM_MODE` / `ICT_CASSETTE` / `ICT_REPLAY_LATENCY_MS`**（已强制忽略，但仍别写）。
5. **DeepSeek 延迟本身有波动**，单次数字有噪声；结果反常时隔几分钟重跑一次再定。
6. **`data/procurement_catalog_2022.json` 必须随部署带上**，见 §0。
