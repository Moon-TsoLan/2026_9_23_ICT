## 每个项目最终提取出的结构化信息如下

一个项目等于「项目名称 + 包编号」。同一采购编号下的不同包是不同项目，不合并。

```
Project 项目级（一个包）
├─ project_id                 由项目名称与包编号组成，全局唯一
├─ source_project_no          公告原文中的项目编号，可空。只作来源，不把不同包合成一个项目
├─ project_name               项目名称
├─ package_no                 包编号，字符串。可为 "1"、"4"、"A"。原文未写包号时为 "1"
├─ purchaser                  采购单位
├─ package_total_amount       该包金额，人民币元。可空
├─ cobs[]                     COB 列表，最细标的物级
│  ├─ object_name             标的物名称
│  ├─ category_code           品目编号。对到 2022 目录的哪一级就写哪一级，可空。不补正文里没有的更深编号
│  ├─ category_name           该编号对应的名称，可与编号相互补全
│  ├─ category_type           A货物 / B工程 / C服务。编码为空时仍可依表头填写
│  ├─ brand                   品牌。货物可能没有注册品牌，服务和工程经常没有，可空
│  ├─ product_supplier        产品供应商。可空
│  ├─ spec_model              规格型号。服务、工程经常只有服务范围等，可空
│  ├─ unit_price              单价，人民币元。这一格自己的单位是「万元」时乘以 10000
│  ├─ quantity                数量。不根据单价和总价倒推
│  ├─ unit                    单位（批、个、把、台等）
│  └─ total_price             总价，人民币元。单位规则同单价。缺总价且单价、数量都有时，用单价乘数量补上
└─ subs[]                     SUB 列表，供应商级
   ├─ supplier_name           投标供应商。联合体整体算一家，不拆开
   ├─ score                   综合得分或评审总得分。原文只有分项得分时为 null
   ├─ is_winner               是否中标
   └─ cooperative_product_suppliers[]  合作产品供应商。仅 is_winner 为真的供应商填写
```

中标/成交公告集合 N = {n1, n2, ...}，共 1038 个。

附件集合 A = {a1, a2, ...}。一篇公告至多对应一个附件压缩包。

关系：

一个公告可以包含多个包，包号可以不连续，例如同一篇里只有采购包 1 和采购包 4。

每个包单独成为一个项目。项目键是项目名称加包编号。

每个项目含若干标的物，由若干投标供应商竞争。供应商对一个包的一次竞标算一次竞争。

附件先绑定这篇公告，再分到该公告里的包。分不清属于哪一包的附件，只用来补这一篇公告中各包的字段，不拿到别的公告里用。

---

公告概要里的总中标金额或总成交金额，是这一篇公告所含各包金额的合计，不是跨公告的整个采购活动总额。

这篇公告只有一个包时，该合计就是这个包的 `package_total_amount`。

这篇公告有多个包时，各包金额以正文或附件里写明的包级金额为准。合计金额不写入每一个包。某个包没有单独金额时，该包的 `package_total_amount` 留空。

---

每个项目至少有一个标的物信息块（COB）。无人中标不会发结果公告；中标供应商至少提供一种标的物，信息在公告或该公告的附件里。

**标的物信息块（COB）**

| | |
| :---: | --- |
| **标的物名称（货物/工程/服务）** | 从该包对应的 HTML 或该公告附件提取 |
| **品目编号** | 按 2022 目录对到哪一级就写哪一级。对不上则空。第一版不推理补更深的级别 |
| **品目编号对应名称** | 与编号相互补全 |
| **品目类型** | A 货物 / B 工程 / C 服务 |
| **品牌** | 多见于货物。未注册品牌、服务、工程可以为空 |
| **产品供应商** | 提供该标的物的厂商或经销商。可以不是投标供应商，也可以就是中标供应商 |
| **规格型号** | 从 HTML 或附件提取。服务、工程可以没有 |
| **单价** | 只看这一格自己的单位。格内或该列标明万元时乘以 10000。附近其它格子写着万元时，不因此换算这一格 |
| **数量** | 只取原文数量。不用总价除以单价来补 |
| **总价** | 单位规则同单价。原文没有总价、同时有单价和数量时，总价 = 单价 × 数量 |

---

**投标供应商信息块（SUB）**

| | |
| --- | --- |
| 投标供应商 | 参与该包投标、并且通过资格性审查的供应商。未通过资格性审查的主体不进入本列表。联合体写成一家供应商，不按顿号或「联合体」拆成多家。完全同名视为同一家 |
| 竞标得分 | 取综合得分或评审总得分。原文没有综合得分、只有技术分或商务分等分项时，填 null |
| 是否中标 | 该包的胜出者为中标供应商 |
| 合作产品供应商 | 仅中标供应商填写。取该包全部 COB 的 `product_supplier` 的并集，去掉空值。中标供应商若也是其中某些标的物的产品供应商，这个名字留在并集里，不因为它同时是中标供应商而删掉 |

---

语义：

采购单位：发布该采购的单位。

投标供应商：通过资格性审查并参与该包竞争的供应商。未通过资格性审查的不算。

中标供应商：该包的胜出者。成交供应商按中标供应商记。

产品供应商：提供包内标的物的厂商或经销商，可能没有参加投标。中标供应商自己供货时，它同时是产品供应商。

合作产品供应商：该包中标标的物的产品供应商并集，挂在中标供应商上。包含那些由中标供应商自己提供的标的物所对应的产品供应商名字。

联合体：一家独立供应商，使用公告中的联合体全称。

---

项目流程

```
1. 提取：一个公告按包拆开。每个包输出一个 Project JSON。
2. package_no 用字符串。原文是 A、B、1、4 都原样保留。没写包号时写成 "1"。
3. 附件先绑到这篇公告，再分到包。不按采购项目编号把附件挂到其它公告的包上。
4. 同一项目名称 + 同一包编号出现多条时，保留非空标的字段更多的那一条。
5. 没在公告或附件里出现的包不补造。
6. 概要中的总中标/总成交金额是本公告各包金额之和。单包时写入该包；多包时各包用自己的包级金额，合计不摊进每一个包。
7. 单价、总价只按该格自己的「万元」换算。总价可以按单价乘数量补齐。数量不倒推。
8. 品目写实际对上的那一级。第一版不把上级名称推成更细的叶子编号。
```
