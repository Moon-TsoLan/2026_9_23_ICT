# 附件抽取错误记录与重设计边界

日期：2026-11-16。本文记录已核实的旧流程错误、用户确定的名词及后续协作约束，不提出新附件方案，不构成代码实现指令。

旧流程规范已[归档](archive/附件旧流程-20261116/README.md)，原入口仅留失效提示。归档不代表代码已改，也不抹除历史实验结果。三表目标与字段含义继续以[任务目标与最终字段口径](任务目标与最终字段口径.md)为准，运行字段定义仍只在fields.py维护。

## 1. 页、分块与上下文的定义

| 名词 | 本次讨论的含义 | 旧实现中的混用 |
|---|---|---|
| 文件 | 一个附件，可能含多页、多个标段或多个业务内容 | 文件进入流程不等于其全部内容已被模型理解 |
| 页 | PDF、DOC等文档中完整的一页，可为文字、文字与图像、纯图像 | 原生DOCX被当作一个逻辑单元，Excel工作表被当作一个单元，与物理页共用page_no及部分预算计数 |
| 分块 | 旧实现按约6000字符切分后的一段原文 | 逐页切分，不跨页组合；短页仍各占一块，长页再拆多块，实际不是按业务关系组织上下文 |
| 模型输入上下文 | 某一次请求实际提供给模型的信息集合 | 不能与页、分块互称；目检可见整页图像及全页原生片段，抽取只见单块及公共任务信息 |

“页”用于指认完整页面，“分块”描述旧实现的文字切分产物；两者不是同一计量单位。新方案是否继续切块、怎样控制输入和预算，等待用户重新设计，不能从这些定义自行推导。

## 2. 已核实的旧代码行为

以下数值仅描述被否定流程，不是新方案默认要求。

1. 文件名命中“中小企业声明函”或“残疾人福利”时直接跳过。其余可读文件进入后续处理，不先做统一的文件级业务价值判断。
2. 长PDF超过40页时，按“有表格优先、既有关键词命中次数多优先、页号靠前优先”选40页，再按页号处理。短PDF无需该排名。该排序不能可靠区分本项目报价、历史报价和招标要求；未入选页无法交给模型纠正。
3. 无图像的原生内容直接进入抽取路径。有图像的页由目检模型选择skip、extract或ocr；PDF的图像准备依据嵌入图像检测或原生文字为空，不保证涵盖所有视觉内容。
4. 初步分块先在每页内收集文字和表格行，超长片段按6000字符切开，再按顺序装块。没有普遍的相邻块重叠，也不跨物理页自动保持关系。PDF整页文字与单独表格行还可能重复。
5. 目检接收整页图像与该页全部初步分块中的来源片段；此处没有按后续30/100分块预算截断。目检只返回读取决定及审计说明。
6. 目检后，先按文件、页的现有顺序保留每文件最多30个页级任务、每公告100个页级任务。无图内容没有事前业务价值比较，也会消耗这层名额。
7. 只有选择ocr且通过前一层预算的页才送OCR；OCR结果替换该页原生抽取内容，然后重新按文字分块。一页可以产生多块，并非一页固定一块。
8. 最后再按顺序保留每文件30块、每公告100块，超额记为未覆盖。此处没有分块重要性评分或模型统一分配预算。

因此旧流程并非单纯“选40页，再选30块”：30/100同时作用于页级任务和最终分块，存在两次截断。

## 3. 定义与职责冲突造成的错误

- **把资源上限变成内容取舍。** 文件、页、分块顺序决定谁先占名额，重要内容没有得到更可靠的进入机会。规则选页也仍保留关键词和版面偏向。
- **把完整本地读取描述成完整模型理解。** 本地读取、模型目检、OCR、候选抽取是不同动作；局部有原文不代表全部内容实际参与抽取。
- **目检依据与执行对象脱节。** 模型基于全页文字判断“原生已足够”，后续抽取却拆成独立块，部分块还可能被预算排除。选择extract没有保证被判断为足够的那份信息完整到达消费者。
- **按页与按字符双重切断关系。** 前页的供应商、项目范围、历史业绩限定、包身份或金额性质，不会自动成为后页/后块的上下文。来源编号和表头只能部分缓解，不能替代这些关系。
- **已OCR也不保证全部抽取。** OCR后的多块仍可能被第二次预算截断，既损失覆盖，也可能浪费已发生的解析费用。
- **让后半程承担不可恢复的损失。** 合并只能处理已收到的候选和证据，无法可靠恢复此前未读到或因上下文缺失而未抽出的信息。
- **把执行验证当成设计有效性的依据。** 接口可运行、字段能传递、短明细得分较好，不能证明长附件的覆盖和连续理解已解决。

已确认的场景是同一案例含历史记录、纯文本标段报价、图文混合的另一标段报价、图文混合招标文件。旧链路没有在它们之间统一理解业务角色后再分配读取与抽取责任。历史记录或招标文件原生文字可先占预算，本案报价反而排在后面。

短报价明细集中、长招标文件多承担补全任务，可能掩盖上述问题。这是与现象相符的解释，尚未经过专门分层统计，不能写成已证实的唯一原因。多页PDF即使总字数少于6000，也通常不会合成一块。

## 4. 需要纠正的旧文档表述

| 旧表述 | 正确的历史事实 |
|---|---|
| 完整读取并抽取附件 | 仅覆盖预算内、成功读取且最终入选的内容 |
| 按上下文切分 | 实际逐页处理，页内超长再按字符拆分 |
| 40页预算、30上下文预算职责明确 | 30/100也用于OCR前的页级截断，计量单位混用 |
| 模型逐页判断保证重要内容进入 | 模型看不到规则排除页，已判断有用的页仍可能被预算截断 |
| 结构信号排名不判断内容价值 | 关键词与表格优先会实际影响业务内容取舍，泛化问题未被消除 |
| 后半程完整证据可弥补前面问题 | 完整传递已保留证据不等于恢复此前漏读或失去关系的内容 |

3. 不得把旧实现、归档文档、旧测试或历史授权自动当作新方案需求。遇到计划缺项、歧义或实现障碍，说明具体问题，返回讨论，不能自行补一套设计。
