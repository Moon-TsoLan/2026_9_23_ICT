# 官方三表兼容与流程衔接

日期：2026-10-13；2026-10-14 修复编号衔接。用户授权按上一轮详细方案全量实施，明确禁止本轮调用 API 与 OCR 服务器测试。
本轮只进行代码修改、固定模型回答测试、历史过程文件回放、编译与前端构建。

## 数据契约

公告 `schema_version=announcement-v2`，仍为 `packages -> cobs/subs`，不新增供应商角色体系。

- 采购单元：`package_kind=lot/contract_package/unpartitioned/unknown`、`package_name`、`source_package_no`；`package_no` 作为内部引用。
- 第一步只抄原文编号。封装分配唯一引用：标段使用类型命名空间；缺号、重号及保留字冲突分配公告内唯一引用，不丢后一个单元。单个单元不等于未分包。
- SUB 新增 `bid_amount`、`review_status=passed/failed/unknown`、`review_failure_reason`。`supplier_award_amount` 继续独立表示中标份额。
- 投标报价取最终投标/响应报价，评审优惠价不能代替。供应商合并只引用已有观测，原文完整行/段作为阶段证据。
- 审查未知不由分数或中标身份推断；未通过供应商保留，官方类别为其他，原因进入蓝色“通过审查”列。
- 所有金额内部及入库仍为元；展示和导出转万元、四舍五入两位。数量保持数字，单位独立。
- 品牌保持原文品牌字段值，缺失为空；产品供应商不能补品牌。品牌替代产品供应商只用于 03 探索，原字段不写回。已批准的末尾模型自供推断继续单独审计。
- 当前标的规格字段中的定制、国标、按照招标要求提供等写法保留；不从别的对象或层级拼接参数。
- 品目使用当前目录匹配的最细有效名称，额外灰色列为单位、产品供应商、品目编码、品目ABC。

## 15 阶段衔接

| 阶段 | 输入与处理 | 输出及下游责任 |
|---|---|---|
| 公告理解 | 模型判断采购单元类型、原文名称及边界，程序分配内部引用 | 01 保存目录与原始编号，不以单包推断未分包 |
| HTML 表理解 | 输入目录；新增 sub_info 供应商报价/审查/混合角色 | 02 列映射支持报价、审查、原因；混合表不整表标中标 |
| HTML 抽取 | 正文仍整篇；未通过主体保留；原文规格和品牌分别取值 | 03 SUB 新字段进入统一字段壳及来源引用 |
| 统一归属 | 唯一单元快捷路径支持目录原编号对应；其它归属由类型、名称、编号和行/段证据共同交模型；歧义正文金额锚点作为独立观测送模型 | 03b 候选和包金额归属，保留原建议与锚点审计；投标报价不进入包金额通道 |
| 缺口规划 | 已知 SUB 逐候选检查报价/审查；failed 缺原因才补原因；名单发现保持未决 | 04 缺口携带采购单元元信息、target_entity 和目标供应商；有附件即目检供应商名单及字段缺口 |
| 文件目检 | 仍按 needs_hit 放行；审查文字与无价格名单也是有效证据 | 05 found_fields 向下传，硬忽略词及所有页预算保持 |
| 原生抽取 | 复用正式附件抽取器；新候选归属复核后参与重新规划 | 05c 合法字段及接收状态保留；SUB 解决记录须指明唯一来源片段与目标候选，同页多主体歧义不能关闭缺口 |
| 版面解析 | 沿现有嗅探、原生读取和 OCR 路径 | 05b 页号、行片段、表头继续传递；本轮没有访问服务 |
| 页定位 | 输入目录和新 SUB 缺口；已有原编号识别通过目录对应，同号歧义不任选一个；普通包提示继续有效 | 06 输出内部引用或 announcement/unknown；同页多单元保护恢复，不新增标段正则 |
| 附件抽取 | 当前采购单元及完整目录、新字段定义、缺口、来源片段 | 07 三通道保持：candidates/package_amounts/need_resolutions；新 SUB 字段独立接收 |
| 归一化 | 投标报价复用现有金额解析器，单位元；审查做枚举校验 | 08 原文保留，非法值标不可解析，不能变成零；规格文本保留 |
| 合并 | COB 仍 delta-v5 九原语；SUB 选择报价/审查/原因来源，原文引用上下文可读 | 09 完整复制新字段；单条及失败回退保留一致观测，冲突新字段保持未知，记录原因 |
| 8b 修复 | 现有价格检查与修复；SUB 审查和中标决定受保护 | 已确认未通过的供应商不能因旧 hint 恢复中标；报价不用于 COB 对账 |
| 产品供应商补全 | 仅对符合原有条件的最终 COB 问模型自供 | 不补品牌；不使用未通过者作为中标自供候选 |
| 落盘与报告 | 统一模型序列化 | projects.json/report.result 公告 v2，旧 projects 包数组入口保留；共15阶段不变 |

供应商合并正常路径、回退路径和最终 Sub 再构造均传递新字段。新增字段不参与旧候选完整度排序。
原生文件是否可跳过深度解析仍要求原有证据覆盖和模型建议；发现名单任务不宣称已完成。
采购单元目录仍由公告理解建立；附件继续复核现有单元内的归属，不在本次兼容中扩展为附件自动新增采购单元。

## 入库、接口与展示

无新增数据库表或列。`announcement.raw_json.official_result` 保存完整成品，`project_map` 显式记录数据库 project_id 到公告内引用的映射；`sub_results` 继续保留。
有原编号且同类型不重号的新采购单元，业务键使用项目编号（缺失沿用项目名）、类型与原编号，不受同号其他类型单元是否出现影响。缺号或同类型重号时，用公告ID及内部引用限制在本公告内，不将排序生成的 unit 序号跨公告串成轮次。旧未知记录无新元信息时键保持原状，不回写历史记录；跨版本身份不能凭旧裸数字自动对齐。
`server/results.py` 是详情、标签与导出的统一读取适配层。新数据用完整成品；旧数据复用数据库及既有审计，无证据的新字段保持未知。

- `/api/objects/export` 现在导出 XLSX。无过滤导出全部公告，包括无 COB 包；有过滤按命中的公告导出完整三表，避免跨表缺失。取消原 5000 行截断。
- `/api/announcements/{announcement_id}/export` 导出单则公告完整三表，01上传记录页已完成行提供XLSX下载按钮。
- 检索、详情、图谱标签使用采购单元名称，旧未知名称显示“采购单元 编号”，不伪造未分包。
- 金额 API 字段继续为元；前端显示万元两位，金额筛选输入万元、请求换回元。品牌检索及显示使用品牌原值。

## XLSX 与金标读取

三表名称及原有列顺序与官方样例一致，21个蓝色必需表头、官方灰色列保留；标的表追加4个灰色表头。导出数据为可评分原值，原文以字符串保存，不能成为公式。
总表每个中标人一行。单一中标人未给份额时使用本包已确认中标总额；多个中标人仅用各自明确份额，未披露不复制整包金额。无中标人仍保留采购单元行。
单价、总价、报价和中标金额用 Decimal ROUND_HALF_UP 转万元，单元格数字格式0.00；空值与0.00区分，总价不从舍入后的单价重算。

`ict.official.read_gold_workbook` 按表名和表头读取新金标，跳过说明及示例标记行，仅数据格底色用于推理格判断，白底不豁免。`score_gold_cell` 实现已确认政策：普通空值拒绝多抽，填色格接受正确值或空，普通有值格不能漏抽。该读取器不将历史两套标注格式自动混用，不用本轮样例重算旧成绩。
