# 字段标注与评测口径

2026-10-10。依据用户转述的赛题组口径：原文缺失、通过计算或推理补全的字段不计入准确率；留空与合理补全均允许。
这是人工标注和评测协议，不根据被测模型的字段来源自动豁免，不改现有评分器。

## 1. 每个字段分开标“值”和“计分资格”

建议在标注表中为每个字段增加两列：`evidence_state`、`score_policy`。还可单独保存 `reference_value`、`evidence_ref`、`note`。

| evidence_state | 原文情况 | expected_value | score_policy |
|---|---|---|---|
| explicit | 本公告或其附件明确写出且能归属当前对象 | 抄原文语义值 | evaluate |
| absent | 全部相关来源均未找到这个字段 | null | exempt |
| derivable | 没直接写出，但有确定计算或合理推断依据 | null；补全值另存 reference_value | exempt |
| uncertain | 人工也不能确定值、归属或粒度 | null；写争议原因 | review |

exempt/review 不进入字段混淆矩阵的 TP/FP/FN/TN，不因输出为空记成 TN；单列数量和比例，防止靠扩大豁免区抬高成绩。
review 不代表正确或豁免已被裁定，最终需要人工复核。评分范围在跑模型前冻结。
赛题组已明确为可补全的空缺字段使用 exempt；如果另有“原文空缺必须空”的正式口径，应另外制定，不自行混同。

## 2. 三个易错例子

**原文单价 2000、总价 6000，没有数量。** 数量标 derivable/exempt，reference_value=3，note 写公式与来源。留空和合理填 3 均不计字段得分；单价、总价仍 explicit/evaluate。

**十条明细都写了数量，最终按单位分别合并。** 数量信息原文存在，不因为最终值 10/6 是计算得到就自动豁免。人工确认这些是独立采购明细且分组明确后，聚合目标数量标 explicit/evaluate，note 记录成员与求和。若赛题组把此类聚合也列为豁免，单独调整该政策。

**保险服务没有产品供应商，根据中标人是保险公司判断自供。** 产品供应商标 derivable/exempt；推断参考值另存。中标供应商名有原文，仍 explicit/evaluate。模型声称“推断”不能令原本明确写出的供应商自动免评。

原生表写了名称、公告名称为空，附件名称与当前成交行对应明确时，名称仍是 explicit，不因跨文件补全而免评。
服务范围被塞进规格时：原文未提供合法规格，规格是 absent/exempt；可另做“违规填充率”质量检查，不能悄悄改变官方准确率口径。

## 3. 推荐结构

```json
{
  "annotation_id": "case:包1:对象01",
  "package_no": "1",
  "object_name": "设备甲",
  "fields": {
    "quantity": {
      "expected_value": null,
      "evidence_state": "derivable",
      "score_policy": "exempt",
      "reference_value": 3,
      "evidence_refs": ["文件A第2页第4行"],
      "note": "原文单价2000、总价6000，未写数量"
    }
  }
}
```

Excel 可扁平化成“案例、包、对象标注编号、字段、期望值、证据状态、计分政策、补全参考值、来源、备注”十列。
用于匹配对象的名称、包号与 annotation_id 必须另保留，不能因某字段免评而连实体匹配一起跳过。

## 4. 混淆矩阵边界

先按人工确认的包和对象粒度匹配实体，再对 evaluate 字段评分；多抽或漏抽对象仍单独计实体错误。
错误值是否同时计 FP 和 FN、空值是否定义 TN，以及负例全集如何确定，必须固定到赛题组评分器口径。
开放式实体抽取不存在天然有限的“所有未抽对象”集合，不要自行制造 TN 或仅用大批空格抬高 accuracy。
建议同时报告字段 precision/recall/F1、参与计分数、exempt 数、review 数和实体匹配情况；官方矩阵以官方定义为准。
当前实现的 field_bindings/supplier_inferences 可供审查溯源，但不能替人工金标决定豁免。
