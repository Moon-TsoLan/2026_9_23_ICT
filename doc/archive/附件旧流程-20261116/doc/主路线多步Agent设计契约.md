## 1. 责任与数据层次

处理一则公告及其附件，输出公告→采购单元→COB/SUB。内容、采购边界、字段归属和同一性由模型判断。程序只负责结构读取、预算切分、引用校验、数值换算和既有后半程算术，不新增名称词表、内容阈值或案例特例。

公共projects.json保持announcement-v2及现有包内字段；数据库、官方三表、账号隔离和跨公告业务键保持。package_no只作公告内引用，source_package_no保留原编号，package_kind区分标段、合同包、未分包和未知。同号不同类型不混同；缺号与重号一次分配唯一引用。单个单元不等于未分包。

候选是观测，不是最终对象。raw_value、normalized_value和后半程实际消费的字段状态保留；来源使用程序生成的原文引用、表/行坐标、表头单位和报价主体。未知字段保留在既有unmapped_fields与原始答复审计。

## 3. 公告与附件输入

标题与完整概要、其余完整HTML并行各一次调用，脚本和样式移除。正文不按章节词、表角色或预览行数筛选。项目身份正文优先、概要补空，冲突原值留审计；概要品目和概要总额保持自身来源。正文候选按采购单元嵌套，归属不明的顶层候选保留。

项目身份与采购目录为父结构，首次合法后固定顺序、内部引用只分配一次。候选、金额与表注释独立接收；一次协议修复后仍有坏项则隔离并partial，合法项跨修复保留。坏目录不接收依赖候选；修复不得重排目录。非法金额性质原值、路径及合法值进修复反馈和reception审计，不转成unknown。已确定供应商的未修复候选传入现有unresolved，阻止默认政策遮住接收失败。

needs只作任务说明：字段、采购单元、原因、实体及已有目标。无旧目标时发现新对象；有旧目标时补字段。没有need_id、purpose、state、need_resolutions、前后快照、覆盖集合、found_fields交集门、原生复用状态或文件续读模型。

页目检同时接收known_observations：从公告合法候选构造的固定只读快照，含编号、实体、采购单元、原文值、字段状态及引用。附件期间不更新。缺口之外的本案例新业务字段同样可以保留；制造商不当投标人，限价不当成交价。kind、置信度及reason不反向作为代码分流条件。

原生内容完整读取后按既有上下文大小分片，不截掉后续段落、表或工作表。原生抽取为空是有效结果。PDF含图像或无文字时逐页看缩略图：原生内容足够用extract，有用图像或不确定用ocr，无关用skip。图像目检只判断展示页，不替未展示页作结论。OCR结果直接进入抽取，不再次页定位。

旧Office和含图DOCX本地用LibreOffice转PDF以支持逐页预览；转换失败记未处理，不升级为整文件OCR。原生Word/表格坐标为逻辑片段或工作表，转换Office页明确标识，不能假称原DOCX物理页。残留归档不上传；已解出的有效成员继续处理。两项硬忽略词保持。

预算保持，并发按上方2026-11-12调度说明执行：每文件解析40页、抽取30个页/逻辑上下文，每公告100个抽取上下文；长PDF沿用原预算排序。预算外记uncovered，最终partial；不宣称完整。格式错误修复一次，接口或最终格式失败记失败，不自动扩OCR。模型不确定可选当前页OCR，confidence只审计。

## 4. 字段、金额与最终政策

fields.py为当前字段定义、步骤专属含义和新协议示例的唯一来源，当前9版本显式登记，不继承历史版本或运行时update。历史字段块冻结存档。提示词任务文字不重新定义字段含义。修改有效字段块会改变回放内容地址，旧录制不能冒充新调用。

金额原文与原文表头分开保留，沿用现有解析器换算元。金额层级与award/budget/ceiling/unknown性质分开，未知不默认成交。附件金额须经归属，不把公告总额复制给各包、不把包金额复制给多家供应商。品牌与产品供应商分开，原规格栏的定制等写法保留。

原候选报价、成交金额和审查明示结论分别抽取。最终合并修复后统一应用：明确最终报价优先；中标人缺少报价时仅采用明确归属该供应商的成交金额；未明确失败的已确认投标响应主体默认通过。零报价不补；失败及未决冲突不以默认覆盖。政策记录在既有field_bindings，不回写候选，不增加业务状态。缺口计算使用同一政策的可用性判断。

## 5. 后半程与验收

第8步规范v10、merge-objects-v6、merge-subs-v2及delta-v5九原语执行算法保持，7/8/8b/9实现未改；新的完整原文与候选证据通过现有接口传入。默认政策是最终组装动作，不混进来源选择或归一化。

运行报告记录实际阶段、未覆盖/失败上下文、所选OCR页，以及各模型调用的提示词、耗时和usage；失败调用不编造token。selected_pages按抽取上下文计数，parsed_pages按实际OCR返回页计数。文件级结束不再存在，全量完整性也不由发现一条对象推出。

本地验证只证明执行语义和兼容性。当前295 passed、19项数据库集成跳过；真实API公告入口50/50接收，两组47页目检无最终格式失败，拟OCR7/6页；旧失败轮次保留，详见[分层验证](../eval/公告前半程修复与分层验证-20261109.md)。这些是运行验证，三表质量与总成本/耗时仍未验收。OCR服务器不可用，未调用OCR、数据库或部署。模型辅助页参考不当作人工真值。唯一待办出口为[待优化清单](../eval/待优化清单.md)。
