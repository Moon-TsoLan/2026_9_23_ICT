## 任务目标与当前阶段

从本次采购公告及附件形成总表、标的表、投标人表，准确保留本案采购单元、成交标的和投标响应主体及其字段。评价信息价值时，应明确它能支持哪个最终字段、属于哪个本案对象，或解决哪个实际归属/冲突问题。

当前核心指标是：**应读页是否以正确方式进入OCR或直接提取入口，以及多读了哪些页。** 用户确认目标页一旦进入正确入口，即可假定模型能够稳定提取；OCR后提取质量不作为页覆盖验收阻断。38例原文复审已完成。Luna替代方案已废弃；2026-11-10用户开启OCR并授权正常系统20例真实评测，已完成，见[报告](../work/real20-20261110/evaluation/report.md)。三表蓝灰指标与逐页对照统一通过[performance入口](../eval/performance/README.md)离线生成。

历史实验冻结38例，其中4例源为验证码/访问限制下载网页，另2例仅有维护页，共6例没有可读采购附件正文；另有个别文件部分不可用。保留原始文件、旧请求/回答与旧结果；新评审、Luna简易模拟和上轮真实API结果分开记录。内容价值由模型判断，程序仅做读取、分片、引用和统计。不用词表、正则或阈值替模型判断页价值，不因审计调整40/30/100预算、原选页方式或两个硬忽略词。

## 三表粒度与身份

- 总表：每采购单元、每中标供应商一行；多个中标人分别保留。
- 标的表：每个实际成交的独立产品、服务或工程标的一行。整体服务的组成内容、技术条款不自动拆成成交标的。
- 投标人表：每采购单元、每投标/响应主体一行；联合体保持整体，未通过审查主体保留。
- UUID是公告唯一标识，三表一致，不加包后缀。标段/合同包使用原文采购单元名称和原编号关联；同号标段和合同包不混同。内部引用、原编号和展示名称分别保存。
- 序号由程序生成；URL是来源链接。这两项不是模型需要发现的业务对象。

## 总表字段

| 最终列 | 含义与取值边界 |
|---|---|
| UUID | 公告唯一标识，保留原样 |
| 标段/合同包 | 本行所属采购单元，保留原文类型、名称和编号，未分包与未知分别表达 |
| 项目名称 | 本次采购项目名称，保留原文完整范围 |
| 采购单位 | 本次采购的采购人，不是代理机构或历史合同客户 |
| 中标供应商 | 本采购单元实际中标/成交供应商，不把推荐排名直接当中标 |
| 中标金额 | 明确属于该供应商的成交金额/份额；单一中标人时可以采用明确对应的包成交金额，多中标人份额不明时不向每人复制整个包金额 |

## 标的表字段

| 最终列 / 内部键 | 含义与取值边界 |
|---|---|
| UUID、标段/合同包 | 同上，用于确定当前标的的公告与采购单元 |
| 产品服务名称 / object_name | 实际成交对象名称，可能是货物、服务或工程；有独立对象证据才能新增成交行 |
| 品目 / category_name | 政府采购目录分类名称，与产品服务名称分开 |
| 品牌 / brand | 原文品牌栏值，含原文写作“定制”等；不以产品供应商或中标人代填 |
| 规格型号 / spec_model | 当前标的原文明示的规格/型号。货物保留其规格栏实际值，包括定制、国标等写法；**服务类通常为空，只有明确出现“规格”或“服务规格”才取值**。不把服务范围、技术要求、服务时间、履约标准、交付/管理方案自动拼成服务规格；由模型理解原文，不实现字面关键词过滤 |
| 数量 / quantity | 当前标的所选计价口径的数量数值，与单位配套；描述中的人数、面积、点位、项目规模不自动成为成交计价数量 |
| 单位 / unit | 台、套、项、人等计价单位，独立于数量保存 |
| 单价 / unit_price | 当前成交标的每个计价单位的金额，必须与对象、数量及计价口径对应 |
| 总价 / total_price | 当前成交标的成交合计金额；预算、最高限价、历史合同金额和未填报价模板不供成交价格 |
| 产品供应商 / product_supplier | 当前货物的制造商或明确供应方、服务的明确承接/提供企业、工程原文明示的承建企业；与投标主体分别识别，不仅凭中标身份认定。工程承建口径由用户于2026-11-10明确确认；已有自供推断单独审计 |
| 品目编码 / category_code | 现行政府采购目录编码 |
| 品目ABC / category_type | A货物、B工程、C服务 |
| 类别 | 当前三表预留灰列，尚无已确认业务定义且导出为空；不为它自行创造抽取任务 |

## 投标人表字段

| 最终列 / 内部键 | 含义与取值边界 |
|---|---|
| UUID、标段/合同包 | 同上，用于确定当前响应主体所在采购单元 |
| 名称 / supplier_name | 本次实际投标/响应主体全称；采购人、代理、专家、制造商、历史业绩客户分别识别 |
| 类别 / is_winner及review_status | 实际中标人、参与人；现行导出将明确未通过审查主体归为“其他”，保留审查原因 |
| 通过审查 / review_status、review_failure_reason | 明确未通过时保留结论及原因。已确认响应主体无明确失败且无相关处理未决时，最终默认通过；原始候选只记录明示内容 |
| 报价（万元） / bid_amount | 最终投标/响应报价优先，首次报价、评审优惠价分别识别；中标人无单列报价时采用明确属于它的成交金额。没有单列报价不等于存在报价处理争议；真实冲突/失败仍留记录，不能被默认值掩盖 |
| 得分 / score | 原文明示综合/评审总得分，JSON输出数字，例如92.4。逐评委分数列表、评分标准满分不填综合分，不自行平均 |
| 未中标原因 | 原文明示未中标原因；与未通过审查原因分开。当前导出尚未接通此灰列，存在的来源证据应在评审中注明“最终列存在、实现未接通”，不混同为目检失败 |

supplier_award_amount是明确属于某供应商的成交金额，承载总表金额及上述报价补值；不是每个标的总价，也不向多家供应商复制包金额。

已知supplier_name不等于已知product_supplier。声明或合同若明确本案产品由某厂制造、服务由某企业承接或工程由某企业承建，可作为标的提供方直接证据；仅重复投标主体名称、企业规模或资质则不足以认定。相对固定公告缺少的制造商/提供方，即使与另一附件同值，也不关闭本页任务。

金额内部按元，展示/三表导出按万元两位；原文金额和表头单位分开保留，现有归一化负责换算。原文、来源、规范值、字段状态与冲突审计保留，但这些审计信息本身不构成额外业务抽取目标。

## 应读页与读取方式的复审口径

1. 先说明本页支持哪个本案最终字段、哪个对象，或解决哪个实际归属/金额性质争议，再判读取方式。只因材料真实、有文字、供应商同名、有合同金额，不足以认定目标页。
2. 本案新的独立成交标的、响应主体、已有对象的新字段均可作为目标，不限于needs；needs是只读重点，不是白名单或完成证明。明示实际报价阶段可以提供此前仅靠成交金额补值所没有的直接证据。
3. 原生文本已经完整呈现目标信息，reading=native；关键值只在图像中或原生缺失关键格，reading=ocr。没有目标取none；项目归属或可读性确实无法确认时单列uncertain，不伪造确定标签。
4. 同页既有无用条款又有有效字段，仍按有效字段保留。原文没有价格不妨碍名称、制造商、明确规格、审查结论等成为目标。
5. 服务范围/方案/技术要求不自动算服务规格；历史项目的客户、标的、金额不转成本次采购对象或报价；资质证书、人员社保、评分标准不当实际审查结论或综合得分。
6. 预算/限价是金额性质旁证。在确实解决本案金额性质或归属问题时可保留；本案成交已清楚、仅新增预算而不能补最终字段时，不自动计应读。没有独立的最终预算列。
7. 纯重复公告已明确字段、空白模板或无支持字段的内容不计有效增量；相同数字若提供了原先缺少的报价性质/对象归属等直接证据，需解释其增量，不能只按数值相同判重复。
8. 跨页表、标题和上下文可作为理解当前页的证据；每个目标仍落到真实页号/逻辑片段。确有表格续页、必要表头或项目范围锚点时注明依赖，避免把历史报价续页误认为本案。

技术章节续页只重复对象标题、继续列功能或交付要求时，不据此把每页都当独立对象增量。明确的采购对象清单与技术功能清单分别理解；读取方式必须核对关键值是否真正存在于原生文本，不能因PDF有标题或页脚就认定无需OCR。

复审先看原文和固定公告快照，再揭示旧动作。Luna标签属于模型辅助原文复核，不称人工金标；争议或不确定标签须独立核对。复核不能更改上轮真实动作。

## 核心指标与计数

- 应读单位：确认应读的物理页与原生逻辑片段分别计数，同时分别列出应OCR与应原生读取数量。
- 覆盖：应OCR页进入OCR入口；应原生页进入原生入口或OCR后可读入口。原生即可的页被送OCR，记覆盖但另计多余OCR；应OCR却只用缺关键值的原生文本，记读取方式错误。
- 漏读：目标未进入正确读取入口，按模型skip、接口失败/未执行、解析预算、抽取预算、硬忽略、源不可读等原因分列。预算损失不能算成模型漏判。
- 多读：无目标信息的单位进入OCR或原生提取；无用OCR与原生路线的无用输入分别报告。原生完整直接提取是已批准路线，不把其全部成本叫作目检模型误判。
- 必须报告不确定单位、未复核单位、不可读文件及预算外范围；没有标签的页不当负例。覆盖率分母仅用已确认目标，并注明是否完成全文件/全案例复核。
- 上轮真实目检决定、预算后排程入口、实际OCR/抽取服务调用分别计。服务器未运行时不能把排程回放说成已执行OCR；按本阶段口径，入口可作为成功依据。
