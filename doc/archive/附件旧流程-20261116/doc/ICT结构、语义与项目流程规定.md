## 公告、采购单元与对象

公共`projects.json`是`announcement-v2`公告对象，包含公告标识、项目概要及`packages`。每个采购单元包含`cobs`标的物列表和`subs`供应商列表；不是单独一个Project，也不是仅有包数组。09合并产物及兼容接口仍保留采购单元数组入口。

```text
公告 announcement-v2
├─ announcement_id / 项目概要 / summary_amount
└─ packages[] 采购单元
   ├─ package_kind / package_name / source_package_no
   ├─ package_no 公告内引用 / package_total_amount
   ├─ cobs[] 标的物、品目、品牌、规格、数量单位与价格
   └─ subs[] 供应商、中标身份、得分、报价、审查与成交份额
```

`package_kind`区分标段、合同包、未分包与未知。`source_package_no`保留原编号，`package_no`为内部引用，两者不能互换：同一个数字可分别属于标段和合同包；缺号、重号也要保留不同采购单元。只有原文明示未分包才展示“未分包”，单个单元或内部引用“1”不等于未分包。

图中每个项目节点、数据库project记录仍对应一个采购单元的一轮。跨公告业务身份区分类型与原编号，缺号或同类型重号限定为公告内身份；不能再概括为全局“项目名+包编号”键。旧未知记录没有新元信息时保持原有业务键，不回写或凭裸数字自动对齐。

附件先绑定本公告，观测归属由统一采购单元归属组件处理。候选行是观测，不是最终对象；无名候选、未决归属与来源冲突都有审计，不能直接填入所有采购单元。

## 标的物与金额

最终COB需有证据支持的名称；仍缺名的组进入未决记录。不预设每个单元一定提取到标的或中标人，也不凭业务常识补造对象。

品目使用当前目录匹配的最细有效名称，编码与ABC独立保存；不把上级名称推成无证据的叶子编号。规格保留原文明示的定制、国标等写法。品牌与产品供应商分别保存，产品供应商不回填品牌；已批准的末尾模型自供判断及其来源审计继续保留。

抽取、存储和API金额均以元表示，展示和官方导出换算万元两位。数量数值与单位独立；数量不由总价除单价倒推。缺失总价可在字段采用之后按有效单价与数量计算，并记录依赖；被否定或禁止的字段不能借计算重新出现。

公告金额、包金额、供应商报价和供应商成交份额层次不同，金额性质另行记录。不能把未知金额预设成成交金额、把项目合计重复填入每包，或把投标报价当作标的总价。包内多个中标人未披露个人份额时，官方总表不为每人重复整包金额。

## 供应商身份与审查

供应商按采购单元记录参与、中标及相关字段；联合体保留原文整体，不拆成多家。身份同一性和角色由当前包内供应商合并组件判断，不用新增符号规则或名称词表替代模型。

未通过审查的主体仍保留在SUB及官方投标人表，`review_status`和`review_failure_reason`分别记录结论与原因，官方类别输出“其他”。中标身份、推荐名次和审查结论不能互相代替；候选只记明示审查，最终未明确失败的已确认主体默认通过，已有冲突未决保留，8b不得恢复模型已明确否定的中标身份。

`bid_amount`优先取明确最终投标/响应报价；中标人缺报价时最终采用其明确供应商成交金额，政策来源单独审计。`supplier_award_amount`仍保留该供应商成交份额。得分仍取原文综合/总评审得分。新字段冲突或无证据时保持未知，旧记录不会自动长出这些信息。

企业身份与关系角色分开；产品供应商可能未参与投标，也可能就是中标人。03探索可在产品供应商缺失时显示品牌替代主体，品牌用独立身份；该替代不写回COB，不进入品牌/产品供应商导出的原字段。完整展示语义见[03探索说明](03探索按需补载与状态恢复-20261014.md)。

## 流程、持久化与交换

主流程注册9阶段：公告概要/完整正文并行理解、一次只读缺口、附件逐页读取抽取、按需统一归属、归一化、合并、检查修复、供应方判断及最终政策、落盘报告。删除旧文件复核和需求关闭链路。步骤产物、来源引用、逐字段采用及事务回滚以现行契约为准，不使用旧说明中的九步或“按非空字段最多保留整条”概括。

数据库表结构保持兼容；公告raw_json保存完整`official_result`、`project_map`及相关审计，读取适配层供详情、标签和导出复用。官方交换使用总表、标的表、投标人表三张XLSX，保留蓝色字段及原有灰色列，另加单位、产品供应商、品目编码、品目ABC灰色列。UUID按公告唯一标识。

检索导出按命中公告完整三表，也可单公告下载。新金标读取使用表名/表头并保留数据格底色；普通空格有抽取算错，普通有值格漏抽算错，填色格接受与金标一致或为空。来源为推断不能让模型自行免评，计分政策见[字段标注与评测口径](字段标注与评测口径.md)。

验证状态以README和实施记录为准，真实模型/OCR复测、完整关系核对及GPU性能验收统一归口[待优化清单](../eval/待优化清单.md)。
