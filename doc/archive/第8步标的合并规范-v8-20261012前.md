# 第 8 步标的合并规范

版本 v8，2026-10-10，当前实现协议 `delta-v4`，提示词 `merge-objects-v4`。
旧 v7 已移至 [历史快照](archive/第8步标的合并规范-v7-20261010前.md)，其自动捐字段、旧组别名和金额选读法不再适用于在线 v4。
实现：`src/ict/merge_protocol.py` 与 `src/ict/steps/s08_merge.py`。

## 1. 输入和判断权

每包有 COB 候选时调用一次模型，单 HTML 候选也调用，才能拒绝误填规格。
模型看到本包全部候选、基线组、来源、报价主体、字段状态、结构标记、只读证据及公告品目。
同名候选形成基线组；每个无名候选单独一组。基线只是召回组织，模型负责同一性、粒度、重复与累加判断。
程序只验证引用、成员集合、供价资格和算术。confidence 与思考内容不参与选择。

## 2. 引用及执行阶段

| 引用 | 含义 |
|---|---|
| `g:0` | 输入基线组；旧数字 0 仍可表达这个初始组 |
| `g:tai` | split/merge 经 as 声明的活组 |
| `c:cand_000001` | 输入候选；旧裸候选编号也兼容 |
| `r:tai_sum` | sum 经 as 声明的计算读法 |
| `p:amount` | 具备资格的本包成交金额，只能供 total_price |

输出 `{"deltas":[],"quantity_accounting":[]}`，不用输出新 COB 或数字。
先按输出顺序执行拓扑（exclude/split/merge），再字段否定，再计算与取值。
split/merge 消耗的旧组立即失效，不自动指向第一个子组；新组与读法编号不得重复。
任何阶段非法都回滚本包全部操作，候选原文不受污染；不是“先合法几条就先改几条”。

## 3. 九种原语

| 操作 | 参数 | 实际语义 |
|---|---|---|
| exclude | candidate_id 或 candidate_ids、kind | 从输出成员退出，证据仍可引用；不自动供字段 |
| split | group_id、parts[{as,members}] | 至少两个子组，无遗漏、无重复覆盖原组 |
| merge | group_ids（兼容 groups）、as | 至少两个不同活组形成一个新组 |
| fields_reject | target、keys | 候选字段不再可供值，或最终组字段显式置空；不能否定 object_name |
| sum | group_id、sources、as | 声明计算读法，可引用已声明 r:；不代表最终采用 |
| name_from | group_id、candidate_id | 只取名称，不顺带继承价格、数量或规格 |
| fields_from | group_id、candidate_id、keys、mode | 描述字段 fill 补空或 select 显式选择覆盖；不能用于名称、计量字段 |
| price_from | group_id、source、可选 keys | 显式绑定计量字段到候选/计算读法；不再被金额对账替换 |
| category_from_announcement | group_id、raw_item | 选输入原文品目，目录查表，只补空 |

kind 为 subtotal_row/project_row/index_row/not_an_object。每条应写 reason；confidence 仅审计。
组内描述默认按既有来源排序补空，有冲突且未显式选择则记录 conflict。跨组或排除来源必须点名目标和字段。
最终同一字段不得重复绑定或同时绑定与否定。最终否定形成 forbid_inference，后续不能复活。候选的数量或单价被否定时，由它们计算出的总价也失效，不能通过旧计算值绕过否定。

## 4. 计量与金额保护

sum 的每个叶候选只可计一次；其成员须属于目标组或已排除证据，不能搬走另一活组计量观测。
所有叶子均须有供价资格。既有计算器检查数量、单位和单价可相加；台与个不做同义换算。
price_from 默认绑定四个计量字段，keys 可选部分；只有数量/单位时要明确 keys，不能冒充完整报价。
p:amount 默认且仅绑定 total_price，最终必须只剩一组且 package_amount_bindable=true。
附件补出的包金额仍仅按既有保守口径存包级，不自动成为单标的价格。

无显式绑定时，从一条具备资格的来源取默认计量组合；无价格时仍保留观测到的数量/单位。
同组未采用的数量/总价观测须在 quantity_accounting 逐项说明 duplicate、alternative 或 unresolved，并给 relates_to、reason。
程序只校验解释的引用，不按同文件、同名或数值相等推定重复。缺解释或 unresolved 使输出 partial。
已采用的观测不能同时标为未采用。排除行由 exclude 的内容判断说明退出理由。

包金额差异继续做检查，不用“凑齐包金额”来选回单行。v4 不生成旧价格替换 alternatives，8b 不能暗改已绑定价格。
招标需求及明确非中标报价保留描述证据，但不能供价或凭自身新增成交 COB。

## 5. 例：十条终端管理器

原组 g:0 拆成 g:tai 与 g:ge；分别声明 r:tai 和 r:ge，然后分别 price_from。
台组数量 1+2+1+1+2+2+1=10；个组 2+1+3=6，单价均 2000，金额分别 20000 与 12000。
求和由程序重算。只声明 sum 而不绑定不会偷偷采用；剩余观测必须说明去向。
独立 P10 明细仍可合成 1728 块；这不是同名行一律相加的规则。

## 6. 例：无名成交行与招标概述

HTML 具备成交金额和数量但名称为空，保留独立组。
招标概述提供本包整体名称时，name_from 指向该观测；HTML 成交价格及数量继续取 HTML。
招标预算留为 budget，需求中的线路组成不因列名完整就新增独立成交标的。
点位参数不自动捐给整体服务；若原组已有服务范围等误填规格，fields_reject 明确置空。
仍不能支持名称的组进 unresolved，不生成假名 COB。

## 7. 审计与回退

- merge_decisions：accepted、applied、sequence、filled/computed；合法未实际填空可 applied=false。
- field_bindings：包、活组、最终 cob_index、字段、值、来源、source_refs、source_candidate_ids、method 与 forbid_inference。
- method：observed/selected/calculated/rejected；供应方补全另记 inferred。
- quantity_accounting、unresolved、conflicts 保留未采用观测与未决理由。
- 非法输出重试一次，仍失败记 merge_model_fallback，事务回滚的 delta 记 transaction_rolled_back。

`llm=None` 保留旧确定性基线；模型失败退回同一基线并明确 partial。这条路径不保证 v4 的字段绑定语义，不能与成功模型计划混称。
固定回答单测只验证编译与执行，不能证明模型在复杂跨文件证据上必然作出正确判断。
