# 提示词编写规范

版本：v1 · 日期：2026-09-29 · 适用范围：`src/ict/prompts/*.md`

---

## 0. 目的与依据

本规范约束本项目各步 system 提示词的写法，用来消除"示例泄漏"和"补丁式规则"，并把能确定的东西交回代码。

依据有两部分：

- 项目自身契约：`doc/主路线多步Agent设计契约.md`（字段、枚举、别名归一、各步要求）。
- 外部权威（原文见 `doc/reference/`）：
  - Microsoft Learn《Prompt engineering techniques》
    `doc/reference/mslearn-prompt-engineering-techniques.md`
  - Prompt Engineering Guide（DAIR.AI）《Few-Shot Prompting》
    `doc/reference/dair-fewshot.mdx`

---

## 1. 字段与枚举以契约为准，提示词不重复

- 字段键、枚举、空值语义（`null` / `""` / `"详见附件"`）、`confidence` 范围，一律以契约 §3、§4、§2B.3、§2B.4 为准。
- **模型键别名 → 正式键的归一已由代码完成**（契约 §1.6，别名映射表）。因此提示词不再写"不要输出 `item_name` / `brand_model` / `product_name`"这类别名禁令，也不要重复罗列别名。
- 枚举非法由代码校验并重试 1 次后记 `llm_schema_invalid`（契约 §1.6）。提示词只列本步必须的枚举值，不展开别名表。
- **注意（实测修正）**：代码归一的是**字段键名**（如 `item_name`→`object_name`），**不是值**。包号**值**的归一（如"第3包"→"3"）**只在页定位做了处理，候选层没有**。因此凡输出包号的提示词，必须保留一句通用格式要求："只写编号本身，例如 3、A，不要写成'第3包''包3'这类形式。" 这不是特例规则。

## 2. 示例只用合成的通用样例

- 依据：示例会把"输入分布"带进模型（DAIR 引 Min et al. 2022），示例主要用来教**格式与字段口径**，不是用来教推理。
- **禁止**把任何真实公告的原文放进提示词：真实表头、单元格值、公司名、项目名、具体数字都不行。
- 允许的人工合成示例：占位值（如「示例公司」「示例型号」），且不得与任何评测样本重合。
- 能不写示例就不写；需要教格式时，用"输出 schema / 骨架"代替具体例子。

## 3. 必须给模型"出口"

- 依据：Microsoft Learn "Give the model an out"——明确允许"找不到就说找不到"，能显著减少编造。
- 每条提示词结尾都必须明确：**无法判断、字段不存在、不可确定时 → 输出 `null` / `unknown` / 空列表**，不得猜测、不得编造、不得补邻近的值。
- 与契约 §3.2 空值语义、§6.4 输出约束保持一致。

## 4. 结构顺序（含末尾复述）

建议顺序：

1. 一句话任务（你要做什么）
2. 输入说明（用户会给你什么）
3. 字段字典 / 枚举（引用契约章节，不重复别名）
4. 判断准则（只写通用规律）
5. 输出 JSON 结构
6. **末尾复述 2–3 条最关键约束**（利用 recency 偏置）

依据：Microsoft Learn "Start with clear instructions" / "Order matters" / "Best practices"。

## 5. 只写"通用规律"，特例不进提示词

- 判据：这条规则覆盖的是"同类的一批"，还是只覆盖我们见过的一篇？
- 后者（例如"一标段 / 二标段不算多包""括号前的数字是综合得分"）**不写进提示词**，应作为代码规则或金标口径另行处理。

## 6. 结构约束优先于口头禁止

- 能由枚举、字段集合、schema 表达的，交给代码校验，不要用自然语言反复叮嘱。
- 需要模型判断的，写"判断标准"，不写"禁止词表"。
- 依据：Microsoft Learn "Specifying the output structure" 可降低编造。

## 7. 空间效率

- 多行数据优先用表格表示，少用逐字段 JSON（Microsoft Learn "Space efficiency"）。
- 输入已经是截断片段时，提示词不要重复大段说明。

## 8. 版本与变更

- **文件名保持不变**：代码里 `prompt_version` 是写死的（如 `triage-files-v1`），文件名被改动会导致代码读不到。因此不重命名，只覆盖同名文件。
- 版本记录改在 `src/ict/prompts/CHANGELOG.md`：日期 / 改了什么 / 为什么 / 依据。
- 旧版本存档在 `src/ict/prompts/_archive/<日期>/`，保留原名，便于回滚与对比。

## 9. 提交前 Checklist

- [ ] 没有任何真实公告原文示例
- [ ] 字段与枚举和契约一致，且没有别名禁令的冗余
- [ ] 结尾有"无法判断 → null / unknown / 空"的出口
- [ ] 关键约束在末尾复述过
- [ ] 没有只覆盖某一篇的特例规则
- [ ] 版本号与 `CHANGELOG.md` 已更新

```text
你是<角色>。<一句话任务>。只输出 JSON：<结构>。

输入：<用户会给出的字段说明>。

字段 / 枚举：见契约 <章节>。<只列本步需要的>。

判断准则：
1. <通用规律>
2. <通用规律>

输出：
{ ... }

无法判断时输出 <null / unknown / 空列表>，不得猜测。
```
