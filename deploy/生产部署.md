# 生产部署（阿里云 Ubuntu 24.04 · 2 核 4G）

面向：一台应用机（公网 IP + nginx 已就绪）+ 一台已在跑的 GPU 解析机。
每步都给了**预期输出**，对不上就停下看第 11 节。

## 0. 一页速览

```
阿里云 2C4G（应用机，公网 IP:80）
  docker compose  ->  PostgreSQL（只在本机 15432）
  ict-api         ->  uvicorn，只监听 127.0.0.1:8000
  ict-worker      ->  提取工作进程（唯一一个）
  ict-tunnel      ->  SSH 隧道到 GPU 机解析服务（127.0.0.1:6008）
nginx           ->  静态文件 /var/www/ict（由 web/dist 同步而来）+ /api 反代到 8000
GPU 机（已有）
  vLLM 6006 + 解析服务 6008（--workers 4），只绑回环，靠上面的隧道访问
```

目录约定（本文都用这套，别改）：

| 路径 | 内容 |
|---|---|
| `/root/workspace/ICT` | 代码仓库（含 `.venv`、`.env`、`web/dist`）—— 就是你说的 `~/workspace/ICT` |
| `/root/workspace/ICT/var` | 运行数据：`tenants/`（上传原件/解压产物/run）、`jobs/`（任务）、`tmp/` |

> 两处都在 `~/workspace`（数据盘）下，对——`var/` 会随批次增长，别放系统盘。
> 若你的路径与本文不同，**只改这 6 个文件里的路径字符串**即可：`deploy/systemd/*.service`（3 个）、
> `deploy/nginx-ict.conf`、`deploy/install_app.sh`，以及本文档。

**只有两样必须手工传**（`git` 拉不到，见 `.gitignore`）：

1. `.env`（DeepSeek key、数据库、GPU 机 SSH）
2. `data/procurement_catalog_2022.json`（1 MB；缺了**每则公告第一步就崩**）

## 1. 前置

### 1.1 安全组（阿里云控制台 → 安全组 → 入方向）

| 端口 | 来源 | 说明 |
|---|---|---|
| 80 | 0.0.0.0/0 | 对外提供页面（没域名就先 http） |
| 22 | **只填你自己的出口 IP** | 别对全网开 |

**不要**放行 5432 / 8000 / 6008 —— 它们只在机器内部用。

### 1.2 时区

```bash
sudo timedatectl set-timezone Asia/Shanghai
date                       # 预期：CST +0800
```

### 1.3 基础依赖（Ubuntu 24.04 自带 Python 3.12）

```bash
sudo apt-get update -y
sudo apt-get install -y python3-venv python3-pip git p7zip-full
git --version              # 预期：git version 2.x
```

`p7zip-full` 只有附件里出现**内层 rar/7z** 时才用得到；外层包都是真 zip，Python 自带就能解。

### 1.4 Docker（只用来跑数据库）

```bash
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu noble stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt-get update -y
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
docker --version           # 预期：Docker version 2x.x
docker compose version     # 预期：Docker Compose version v2.x
```

> 不想装 Docker 也行：`sudo apt-get install -y postgresql-16`，自己建库建用户并把 `DATABASE_URL` 指到本机 5432，其余步骤一样。

## 2. 放代码与配置

### 2.1 代码（二选一）

**甲：服务器能访问仓库**

```bash
cd ~/workspace
sudo git clone <你的仓库地址> ICT      # 私有库用 token 或 deploy key
sudo chown -R "$USER":"$USER" ~/workspace/ICT
```

目标就是得到 `~/workspace/ICT`（= `/root/workspace/ICT`）。

**乙：从本机传（没装 git 或连不上仓库时）**

在**本机** PowerShell（仓库根目录）：

```powershell
scp -r D:\all_contest\2026_9_23_ICT root@<公网IP>:/root/workspace/ICT
```

传完把不需要的目录删掉，省空间也避免误用：`work/`、`data/赛题五基准测试数据*`、`web/node_modules`。

### 2.2 两样必须手传的东西

在**本机**：

```powershell
ssh root@<公网IP> "mkdir -p /root/workspace/ICT/data"
scp D:\all_contest\2026_9_23_ICT\.env root@<公网IP>:/root/workspace/ICT/.env
scp D:\all_contest\2026_9_23_ICT\data\procurement_catalog_2022.json root@<公网IP>:/root/workspace/ICT/data/procurement_catalog_2022.json
```

（第一行先建目录：**scp 不会创建中间目录**，父目录不存在就会报 `dest open ... No such file or directory`。
另外注意 `~` 不等于 `/` —— 用 root 登录时 `~/workspace` 是 `/root/workspace`，别写混。）

### 2.3 把 `.env` 改成生产值

```bash
sudo nano /root/workspace/ICT/.env
```

要改/确认的几行：

```ini
# 生产库：库名与密码要和第 3 步的 docker-compose.yml 一致
DATABASE_URL=postgresql://ict:<生产密码>@localhost:15432/ict_prod
PGDATABASE=ict_prod
PGPORT=15432

# DeepSeek
ICT_LLM_BASE_URL=https://api.deepseek.com
ICT_LLM_API_KEY=sk-...
ICT_LLM_MODEL=deepseek-flash

# GPU 解析机（实例重启后 host/port 会变；改完只需重启 ict-tunnel）
ICT_SSH_HOST=connect.xxx.seetacloud.com
ICT_SSH_PORT=xxxxx
ICT_SSH_USER=root
ssh_password=...
ICT_TUNNEL_LOCAL=6008
ICT_TUNNEL_REMOTE=127.0.0.1:6008
ICT_PARSE_URL=http://127.0.0.1:6008
ICT_PARSE_MAX_INFLIGHT=3
```

> `ICT_DATA_ROOT` **不要写进 `.env`** —— 它是进程环境变量，写在 systemd unit 里（第 6 步），值是 `/root/workspace/ICT/var`。

## 3. 建数据库

```bash
cd ~/workspace/ICT
sudo nano docker-compose.yml
#   改两处：POSTGRES_DB: ict_prod、POSTGRES_PASSWORD: <生产密码>
#   顺手把 healthcheck 里的 -d ict_demo 也改成 ict_prod
sudo docker compose up -d
sudo docker compose ps            # 预期：ict-pg  ... (healthy)
```

首次启动时容器会自动执行 `db/001_schema.sql`（**新库只需要这一个文件**，里面已含 `tenant_id`、`package_key/round_no` 与外键级联）。

```bash
sudo docker exec ict-pg psql -U ict -d ict_prod -c "\dt"
# 预期：announcement / project / cob / supplier / bid / winner_coop_supplier
```

> 2 核 4G 想再省内存：把 compose 里 `-c shared_buffers=512MB` 改成 `256MB`。

## 5. 构建前端

```bash
cd ~/workspace/ICT/web
npm ci                 # 按 package-lock.json 装，比 npm install 稳
npm run build          # 预期：✓ built in 若干秒
ls dist/index.html     # 预期：存在
```

> 也可以在本机构建好，只把 `web/dist` 传上去（服务器就不用装 Node）。

**构建产物要放到 nginx 能读的地方（`/var/www/ict`）**。nginx worker 以 `www-data` 运行，而
`/root` 权限是 `0700`，`www-data` 连目录都进不去——直接将 nginx 的 `root` 指到
`/root/workspace/ICT/web/dist` 会让首页 403，配置里再带 `try_files` 时表现为 500。

```bash
sudo mkdir -p /var/www/ict
sudo rsync -a --delete ~/workspace/ICT/web/dist/ /var/www/ict/   # 没装 rsync 就用 cp -r
sudo chown -R root:root /var/www/ict && sudo chmod -R a+rX /var/www/ict
ls -l /var/www/ict/index.html
```

## 6. 装三个 systemd 服务

```bash
cd ~/workspace/ICT
sudo cp deploy/systemd/ict-api.service deploy/systemd/ict-worker.service deploy/systemd/ict-tunnel.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ict-tunnel ict-api ict-worker
```

三个 unit 里都写死了 `Environment=ICT_DATA_ROOT=/root/workspace/ICT/var` —— **后端与 worker 必须一致**，否则 worker 会在另一个目录里空等，任务永远停在"等待中"。

```bash
systemctl status ict-api --no-pager
systemctl status ict-tunnel --no-pager
systemctl status ict-worker --no-pager
```

worker 的启动行是排"两边不一致"最快的凭据：

```bash
sudo journalctl -u ict-worker -n 20 --no-pager
# [worker] threads=2 poll=3.0s data_root=/root/workspace/ICT/var/tenants/default
# [worker] 任务目录 /root/workspace/ICT/var/jobs/default
```

## 7. 配 nginx

```bash
cd ~/workspace/ICT
sudo cp deploy/nginx-ict.conf /etc/nginx/sites-available/ict.conf
sudo ln -sf /etc/nginx/sites-available/ict.conf /etc/nginx/sites-enabled/ict.conf
sudo rm -f /etc/nginx/sites-enabled/default      # 去掉默认站点，别抢 80
sudo nginx -t                                    # 预期：syntax is ok / test is successful
sudo systemctl reload nginx
```

这份配置里有两处**必须保留**，删了就会出问题：

- `client_max_body_size 600m`：上传单文件上限 512MB，nginx 默认 1MB 会直接 413；
- `try_files $uri $uri/ /index.html`：单页应用刷新任意深链都要回 index.html。

还有一处**不能改回仓库路径**：`root /var/www/ict;`。仓库在 `/root` 下，`www-data` 进不去。

```bash
curl -s -I http://127.0.0.1/ | head -3      # 预期：HTTP/1.1 200 OK
curl -s http://127.0.0.1/api/health         # 预期：{"ok":true,...}
```

## 8. 起服务与自检

```bash
curl -s http://127.0.0.1:8000/api/health          # 预期：{"ok":true,"announcements":0,...}
curl -s http://127.0.0.1:6008/health              # 预期：{"ok":true,...,"soffice":true}
curl -s -o /dev/null -w "%{http_code}\n" http://<公网IP>/     # 预期：200
curl -s http://<公网IP>/api/health                # 预期：{"ok":true,...}（反代通了）
```

> 隧道可能比解析服务晚就绪；`curl 6008` 失败先 `sudo systemctl restart ict-tunnel` 再试。

## 9. 上线验收清单（按顺序跑一遍）

1. 打开 `http://<公网IP>/` → 01 采集页正常显示；
2. 传一对 `xxx.html` + `xxx.zip` → 弹窗显示配对结果 → 提交后列表出现**等待中**；
3. worker 自动领取 → **处理中**（显示 `第 N/12 步 · 中文步骤名`）→ **已完成**，项目/标的物有数字；
4. 库里对得上：
   ```bash
   sudo docker exec ict-pg psql -U ict -d ict_prod -c "SELECT count(*) FROM announcement; SELECT count(*) FROM cob;"
   ```
5. 原件已删、run 目录保留：
   ```bash
   ls /root/workspace/ICT/var/tenants/default/incoming/<job_id>/   # 预期：空
   ls /root/workspace/ICT/var/tenants/default/runs/                # 预期：有该公告目录（01–10 产物）
   ```
6. 检索页能查到这批标的；探索页出现「资料库已更新」提示；
7. **故意停隧道**（`sudo systemctl stop ict-tunnel`）→ 传一则带附件的公告 → 该行应为**失败**、原件保留；恢复隧道后重传可成功；
8. **重启 worker**（`sudo systemctl restart ict-worker`）→ 之前卡在"处理中"的行变成"失败（处理中断）"，不会永远转圈。

## 10. 日常运维

```bash
# 日志
sudo journalctl -u ict-worker -f
sudo journalctl -u ict-api -f
sudo journalctl -u ict-tunnel -f

# 改代码后（git 方式）
cd ~/workspace/ICT && sudo git pull
cd web && npm ci && npm run build
sudo rsync -a --delete ~/workspace/ICT/web/dist/ /var/www/ict/
sudo systemctl restart ict-api ict-worker

# 只改了前端（dist 是构建产物，不放进 /var/www/ict 前端就不会变）
cd ~/workspace/ICT/web && npm run build
sudo rsync -a --delete ~/workspace/ICT/web/dist/ /var/www/ict/

# 只改了提示词 / 规则代码：worker 是常驻进程，必须重启才生效
sudo systemctl restart ict-worker

# 备份数据库
sudo docker exec ict-pg pg_dump -U ict -d ict_prod -F c -f /tmp/ict_prod.dump
sudo docker cp ict-pg:/tmp/ict_prod.dump ./ict_prod_$(date +%F).dump

# GPU 机实例重启后 host/port 可能变：改 .env 那两行，然后只重启隧道
sudo systemctl restart ict-tunnel
```

**磁盘**：`/root/workspace/ICT/var` 会随批次增长（run 目录留痕）。代码在余量 <20GB 或 <15% 时会**拒绝上传**，别等它满了才发现。

## 11. 排障表

| 现象 | 多半原因 | 怎么办 |
|---|---|---|
| 上传报 413 | nginx `client_max_body_size` 没配 | 确认配置里有 `client_max_body_size 600m`，`sudo systemctl reload nginx` |
| 页面能开但 `/api/*` 502 | ict-api 没起 | `systemctl status ict-api` → `journalctl -u ict-api -n 50` |
| 任务一直"等待中" | worker 没起，或 `ICT_DATA_ROOT` 两边不一致 | `systemctl status ict-worker`；看启动行的 `data_root` 是否 `/root/workspace/ICT/var/tenants/default` |
| 任务"失败"，错误含 `parse_unreachable` | 隧道断 / GPU 机服务没起 | `curl 127.0.0.1:6008/health`；`systemctl restart ict-tunnel`；必要时上 GPU 机跑 `start_vllm.sh` + `start_parse.sh` |
| 提取结果为空、`cob=0` | 该公告只列了供应商、没有标的明细 | 正常；展开看步骤与计数，必要时人工看原公告 |
| 某行点开显示"没有处理记录" | 这则的 run 目录不在服务端读的位置 | 确认它是走新流程（上传→worker）入库的 |
| worker 报"已经有工作进程在跑" | 上次被强杀留下的锁（新代码会自动接管，除非 pid 还活着） | `ps -p <pid>` 看是否真在跑；不在就删 `/root/workspace/ICT/var/jobs/default/.worker.lock` |
| 刷新页面 404 | nginx 少了 `try_files ... /index.html` | 对照第 7 步 |
| 首页 500 或 403，`/api/*` 正常 | nginx 的 root 指到 `/root/...`（www-data 读不到），或 `dist` 还没 build / 没同步到 `/var/www/ict` | `sudo tail -5 /var/log/nginx/error.log`；确认 `ls -l /var/www/ict/index.html` 存在，root 是 `/var/www/ict` |
| 前端改了但页面没变 | 只 `npm run build` 没同步 dist | 重新 `npm run build` + `rsync -a --delete web/dist/ /var/www/ict/` |
