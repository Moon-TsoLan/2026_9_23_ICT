# 星图 × 五大场景 · 交互设计指引 v3

> 用途：约束"点击节点 / 切场景 / 多选比较"这三件事的语义，避免同一个动作在不同地方被赋予两种含义。
> 代码评审与后续改动都以本文的"不变量清单"为准。

## 0. 一句话

**星图只有一个动作，五个场景是它的五组参数。**

## 1. 核心判断

单击任何节点，高亮方式都一样——这不是设计缺失，而是设计正确的证据：它说明星图只有一个原语。

因此"场景"不应该改变星图怎么画，只应该改变两件事：

1. **哪些边算数**（中标 / 投标 / 采购 / 供货）；
2. **选中集里多进来的那批点**（场景答案）。

推论：

- 总览 = 没有场景时的原语演示（所有边都算数，没有答案集）。
- 场景 = 给原语加了两个参数，不是第五种画法。
- 让"场景"去改变高亮方式，是此前所有冲突的来源。

## 2. 术语

| 术语 | 含义 | 视觉 |
|---|---|---|
| 选中集 | 用户正在发问的对象，1..N 个主体节点 | **带序号徽章 ①②③**，只能显式移除 |
| 临时聚焦 | 鼠标刚点到的那个点，用来预览关系 | **淡描边**，点空白即退 |
| 当前问题 | S1..S5 之一，或"未提问" | 面板下段标题 + 顶部高亮 |
| 答案集 | 当前问题算出来的节点集合 | 提亮 + 命名，参与镜头取景 |
| 边过滤 | 当前问题下"哪些关系算数" | 决定连线颜色与标签 |

**选中集与临时聚焦必须是两套视觉。** 用户看到徽章才会相信"这东西不会被误点掉"。

## 3. 星图原语的三个输入

| 输入 | 由谁提供 |
|---|---|
| 选中集（1..N 个点） | 用户点击 / 场景主体 / 搜索定位 |
| 哪些边算数 | 当前问题（场景）；未提问时全部算数 |
| 镜头看哪儿 | 选中集与答案集的包围球 |

除此之外星图不接受任何模式开关。任何"这个场景下点击行为不一样"的需求，都应翻译成上面三个参数之一的变化。

## 4. 五个场景 = 五组参数

| 场景 | 源类型 | 源数量 | 算数的边 | 要求共同 | 面板形态 | 镜头 |
|---|---|---|---|---|---|---|
| — 未提问 | 任意 | 0..1 | 全部 | 否 | 只有"当前选中"段 | 跟随选中点 |
| S1 长期合作 | 采购单位 | 1 | 中标 + 供货 | 否 | 榜单（次数 / 金额） | 从源点外推一层 |
| S2 高频投标 | 采购单位 | 1 | 投标 | 否 | 榜单 + 协同组合 | 从源点外推一层 |
| S3 同场竞标 | 供应商 | 1 | 投标（经项目二跳） | 否 | 榜单 | 从源点外推一层 |
| S4 共同采购 | 供应商 | N≥2 | 中标 → 采购 | **是** | **矩阵**（行=交集，列=各家） | 拉高，同时框住 N 个源与交点 |
| S5 共同竞标 | 供应商 | N≥2 | 投标 | **是** | **矩阵** | 同上 |

S4/S5 的边**按来源主体着色**（A 家的边一色、B 家的另一色），于是"同时被两色连住"的节点就是真交集——"共同"这件事在图上直接可见，不依赖读面板。

## 5. 点击语义（唯一权威表）

| 动作 | 单选模式（未提问 / S1 / S2 / S3） | 多选模式（S4 / S5） |
|---|---|---|
| 点一个点 | 选中集 = {它} | **加入**选中集 |
| 点空白 | 取消选中，回到未提问 | **只退临时聚焦，集合一个不动** |
| 再点已在集合里的点 | 无变化 | 移出集合 |
| 关注带上的 × | 移出 | 移出 |
| Esc / 清空 | 全部取消 | 全部取消 |
| 拖拽 / 滚轮 | 旋转 / 缩放（不改变选中） | 同 |

要点：**多选模式下"单击"不表示替换**。这样"空白"就不必承担"清空一切"的职责，误点的代价从"丢掉整篮"降为"退掉一个预览"。

## 6. 面板：永远两段

- **上段 · 当前选中**：刚点的节点 + 它的关系摘要（角色、本场景内关系数、排名）。点任何点都有内容，永不空白。
- **下段 · 当前问题**：S1..S5 的答案。类型匹配就出结果；不匹配就**灰着并写明原因**。

点到了与当前问题不匹配的节点时，三件事**都不做**：不报错、不清空选中、**不自动切场景**。只做一件事：下段变成

> S1 需要采购单位 · 你选的是供应商 → 换成 S3 问它

自动切场景会让用户失去"我在问什么"的掌控感，这是此前冲突感的主要来源。

## 7. 默认态

进入探索页 = **未提问**，不是 S1。

理由：S1 预设了"你手里已经有一个采购单位"，而刚进页面时用户没有。默认态就是纯原语：宇宙 + 一句"点一颗星看它和谁有关系"。用户点了采购单位之后，再选 S1 才顺理成章。

顶部五个场景 chip 的定位是**问题目录**（给不知道要问什么的人），不是查询表单的第一步。

## 8. 多选怎么凑够 N 家

1. **关注带常驻**在星图底部，永远显示当前集合：`关注：① 东软集团 × ② 新蓝海科技 清空`。
2. 三个入口，全在同一画面里：星图上点（多选模式）、榜单行上的"加入对比"、⌘K 搜索选"加入关注"。
3. **补一个相似的**：集合里只有 1 家供应商时，给一个按钮"找一家常和它同场竞标的"，直接取 S3 答案第一名塞进集合。三步之内必然能开始比较。
4. 类型守卫：集合内只能同一类源（都是供应商，或都是采购单位）。混入时不报错，问"改成以它为主？"
5. 上限 4 家，到数明确说明，不静默失败。

## 9. 勾选抽屉，而不是新页面

当集合 <2 家而用户点了 S4/S5：**左侧滑出抽屉**（供应商列表 + 搜索 + 勾选），中间星图与右侧面板**全程不换**。

关键规则：**每勾一家，交集实时收窄一次，不需要点"查询"**。看着共同答案从 5 个掉到 1 个，这个过程本身就是 S4/S5 的价值；一次性提交会把它杀掉。

抽屉是临时态，收起后人还在同一张宇宙里——这是消除"和 S1/S2/S3 割裂"的主要手段。

## 10. 画面模型：推进式

- 底图（总览采样图）只算一次，每个节点的坐标**缓存**。
- 场景查询只决定"这次看哪几颗"，镜头推进到它们的包围球；非答案的星与雾淡到 4–6%（接近消失但能感觉到外面还有东西）。
- 退出问题：镜头拉回全景，淡入回来。
- 收益：背景不会"突然刷新"；答案不被埋在噪声里；同一家公司跨场景位置稳定（空间记忆不断裂）；真实规模下只算几十个点。

## 11. 空结果必须降级，不能只说"没有"

S4/S5 在真实数据上经常为空。空结果时自动退一步并说明：

1. 把 N 家降成 N−1 家（"去掉 X 之后，这 2 家有 3 个共同采购单位"）；
2. 或降级成两两视图（不要求 N 家共同，给出每两家之间的交集）。

这让 S4/S5 从"容易查空"变成"能顺着往下钻"。

## 12. 星图的正当性（写进答辩）

表格只能回答你打出来的查询。星图回答的是**"我在看 A 的时候发现了 B，于是想问 B"**。

> 五个场景提供查询能力；星图提供"知道下一个该问哪个场景"的能力——它把五个孤立功能串成一条动线。

同时保留一条底线：星图必须随时能退回纯列表读法（右侧面板就是那个读法），不能为了画面牺牲可读性。

## 13. 不变量清单（评审与自测用）

1. 单击节点的行为在任何场景下都只有一种语义（多选模式=加入，其余=替换）。
2. 点空白永不销毁选中集里的成员。
3. 选中集成员只能通过 × / 再点 / 清空 / Esc 移除。
4. 切换场景不改变"点击语义"，只改变边过滤与镜头。
5. 面板上段（当前选中）永不为空；下段（当前问题）不匹配时给出原因与下一步动作。
6. 不自动切换场景。
7. 同一个节点在不同场景查询中的屏幕位置一致（坐标缓存，不重排）。
8. 答案集节点 100% 有名字（标签避让不得挤掉答案）。
9. 多选集合有类型守卫与数量上限，且两者都在界面上可见。
10. 空结果一定带降级建议，不出现死胡同。
11. 任何时刻界面上能读到一句话：当前问题 = ?，选中 = ?，答案 = ?。
12. 星图与面板对"当前选中"的理解必须一致（不能面板是上次查询、星图是刚点的）。

## 14. 明确不做

- 不做"每个场景一套高亮样式"。
- 不做"切 tab 即换页面/换布局"。
- 不做自动切场景、自动清空选中。
- 不在星图上做框选（与旋转拖拽冲突）。
- 不为 S4/S5 单独开一个三栏工作台。

## 16. 采纳方案：S0 状态机（2026-10-01 项目方提出，取代 §7 与 §9 的入口设计）

一句话：**去掉顶部场景切换，把"未提问"变成正式状态 S0；场景不再是模式，而是"对当前选中对象的一次提问"，问完必须退回 S0。**

### 16.1 四个状态

| 状态 | 进入方式 | 星图 | 面板 |
|---|---|---|---|
| **总览** | 初始 / 从任何状态退出 | 全亮，雾正常呼吸 | 数据规模 + 引导 |
| **S0 选中** | 总览下单击任意节点 | **只亮选中点**，其余全部暗淡 | 基本信息 + **按节点类型给出的场景按钮** |
| **场景态** | 在 S0 选中按下一个场景按钮 | 聚焦该主体，按场景的边角色高亮关系 | 上段基本信息 + 下段场景详情（榜单/矩阵） |
| **多选态** | 在 S0 选中供应商后按 S4/S5 | 结束聚焦，**只亮"有中标记录的供应商"= 可选池** | 当前集合 + 增删 + 查询按钮 |
| **多选结果态** | 多选态点"查询" | 聚焦这 N 家 + 它们的共同邻居 | 矩阵详情 |

### 16.2 转移表

| 从 | 动作 | 到 |
|---|---|---|
| 总览 | 单击节点 | S0 选中 |
| S0 选中 | 单击另一节点 | S0 选中（换对象） |
| S0 选中 | 按场景按钮 | 场景态（S4/S5 → 多选态） |
| S0 选中 | 点空白 / Esc | 总览 |
| 场景态 | 点空白 / Esc / 面板 × | **总览**（不是 S0） |
| 场景态 | 单击其他节点 | S0 选中该节点（一步换对象，不弹提示） |
| 多选态 | 单击可选池内的点 | 加入集合（集合显示在面板） |
| 多选态 | 减到 1 家 | 留在多选态，查询按钮禁用 |
| 多选态 | 点"查询" | 多选结果态 |
| 多选结果态 | 点空白 / Esc / × | **多选态**（保留集合，可微调） |
| 多选结果态 | 增删集合成员 | 留在结果态，但"重新查询"亮起（不自动重查） |

### 16.3 为什么它从根本上解决了冲突

对照审查报告里的三个根因：

- **根因 A（没有"退出问题"的动作）**：S0 就是"没有问题"的状态，每个非 S0 状态都有唯一一条退回 S0/总览的路径。语义超载消失。
- **根因 B（三份"当前主体"）**：主体只存在于"选中集"这一份里；S0 的点击只改选中，不隐含任何查询意图。
- **点击语义冲突（C3）**：从"一个动作跨模式含义不同"变成"**每个状态内点击语义唯一**"——这是设计，不是妥协。

额外收益：**"接力查询"这个功能可以删掉**。退出 → 选中 → 选问题，本身就是接力，少一套 UI、少一处状态源。

### 16.4 需要补的空白（本指引的建议值，待项目方确认）

1. **S0 选中态邻居要不要淡亮？** 建议完全不亮，但面板写"它有 12 条关系，选一个问题来看"——用关系数当钩子，反而比默认亮着更能引导提问。
2. **场景态点其他节点**：建议直接"S0 选中该节点"，一步完成换对象，不弹确认。
3. **可选池的边界**：只亮**有中标记录的供应商**，与"没中过标就不给 S3/S4/S5 按钮"是同一条规则，两处共用一个 `hasWin` 标记。
4. **从未中标的供应商被选中**：面板明确说"它没有任何中标记录，S3/S4/S5 都以中标供应商为主体"，并给一个"看它参与的项目"的 S0 级摘要（不查场景）。
5. **查询结果态能否继续增删集合**：能，但**不自动重查**，改完"重新查询"按钮亮起，避免结果乱跳。
6. **搜索框 / ⌘K / 档案页深链**：一律等价于"在 S0 里选中该节点"，不自动查询。
7. **多选上限 4 家**，界面上写明。

### 16.5 实现成本评估

| 事项 | 量级 | 风险 |
|---|---|---|
| 状态机本身（`mode` 枚举 + 转移函数，替换现在 scene/subjects/result/focus 的自由组合） | 中，**是删代码不是加代码** | 低 |
| S0 只亮选中点 | 一行 target 规则 | 低 |
| 场景态"哪些边算数"过滤 | 小（focusLines 现在收 1.5 跳全部，改成按角色集合过滤） | 低 |
| 可选池高亮（按 `kind + hasWin`） | 小，但**需要节点带 hasWin 标记**（后端一行） | 低 |
| 多选结果态"边按来源主体着色" | 约 60–80 行，**唯一可能需要后端配合的地方**（边上要带"属于哪一家"） | 中 |
| 坐标缓存（根因 C） | 约 40 行 | 中——**必须与本方案同时做**，否则"退回总览"会看到图重排，S0 的连续感就破了 |

### 16.6 不变量更新

- 不变量 1 改为：**每个状态内点击语义唯一**；跨状态不同是设计。
- 新增不变量 13：**任何非 S0 状态，都必须有一条一屏内可见的退出路径。**
- 新增不变量 14：**状态切换不得改变任何已有节点的屏幕位置**（坐标缓存）。

## 17. §16.4 决议（2026-10-01 项目方确认）

| # | 议题 | 决议 |
|---|---|---|
| 1 | S0 选中态邻居亮度 | **不亮**。只亮选中点，其余全部暗淡。 |
| 2 | 场景态点击其他节点 | **不允许**。场景态是"锁定阅读"：可以转视角、可以缩放、可以悬停看全名，但**不能改选中**。要选别的点必须先退出回 S0。 |
| 3 | 多选态可选池 | **不按 hasWin 过滤**。所有供应商都可见可选——用户不知道自己想查的公司中过没中标，藏起来只会让人怀疑"我上传的数据怎么找不到节点"。要收窄就用左下角图例过滤（现成能力）。 |
| 4 | 从未中标的供应商被选中 | 明说原因 + 给一份不查场景的摘要。 |
| 5 | 结果态增删集合成员 | **可以改，但一改就掉聚焦与关系连线**，回到多选态（集合内容保留），直到重新按"查询"。 |
| 6 | 搜索框 / ⌘K / 档案页跳入 | 见 §17.1 说明。 |
| 7 | 多选上限 | **4 家**，界面上写明。 |

### 17.1 关于第 6 条（原话太抽象，重述）

要决定的其实是一个很具体的场景：

> 用户在顶部搜索框打"东软集团"，从下拉里点中它。
> **这一刻应该发生什么？**

两种选法：

- **甲：直接开查**——但查哪个场景？搜索框旁边已经没有场景芯片了（顶部切换被去掉），系统只能猜一个，猜错就得重来。
- **乙：只是选中它**——星图飞过去并进入 S0 选中态，面板显示"东软集团 · 供应商 · 有 8 次中标记录"，下面摆出 S3 / S4 / S5 三个按钮，由用户挑。

**建议选乙。** 理由：这跟第 1、2、5 条是同一个原则——**"选中"和"提问"永远是两个动作，任何入口都不许把它们合并。** 从档案页跳进星图（`/explore?focus=xxx`）同理：只选中，不提问。

### 17.2 由第 2、5 条推出的两个实现要求

第 2 条把"点了没反应"变成设计的一部分，因此**必须把不可点表达出来**，否则用户以为坏了：

1. 场景态下，非答案节点的光标改为禁用态（悬停仍可看全名，只是不给点）。
2. 场景态在星图上保留一条常驻轻提示：**"S1 结果 · 退出后可选其他节点"**，退出按钮就在提示里。

第 5 条让状态机少了一个状态：**结果态与多选态只差"有没有 result"**，一改集合就退回多选态。所以不需要"重新查询按钮亮起"这种中间态。

### 17.3 修正后的转移表（取代 §16.2）

| 从 | 动作 | 到 |
|---|---|---|
| 总览 | 单击节点 | S0 选中 |
| S0 选中 | 单击另一节点 | S0 选中（换对象） |
| S0 选中 | 按场景按钮（S1/S2/S3） | 场景态 |
| S0 选中 | 按场景按钮（S4/S5） | 多选态 |
| S0 选中 | 点空白 / Esc | 总览 |
| 场景态 | 单击其他节点 | **无动作**（光标禁用 + 轻提示） |
| 场景态 | 拖拽 / 滚轮 / 悬停 | 允许（只改视角，不改状态） |
| 场景态 | 点空白 / Esc / 提示里的退出 | 总览 |
| 多选态 | 单击供应商 | 加入集合（已满 4 家则提示） |
| 多选态 | 单击已在集合里的 | 移出集合 |
| 多选态 | 加入未中标供应商 | **不加入**，给第 4 条的说明 |
| 多选态 | 点"查询"（≥2 家） | 结果态 |
| 结果态 | 增删集合成员 | **退回多选态**（掉聚焦、掉连线，集合保留） |
| 结果态 | 点空白 / Esc / × | 总览 |

### 17.4 状态数收敛

原来的"多选态 / 多选结果态"合并为一个（差别只是有没有 result），加上"总览 / S0 选中 / 场景态"，**整套交互只有 4 个状态**：

```
总览 ──点──▶ S0选中 ──按问题──▶ 场景态 ──退出──▶ 总览
                    └──按S4/S5──▶ 多选态 ⇄ 结果态 ──退出──▶ 总览
```

这比之前"scene × subjects × result × focusId"四元自由组合（理论 80 种组合，其中大部分是错的）小两个数量级，也是这个方案真正值钱的地方。

## 18. 搜索入口的状态规则（§17.1 定稿）

**原则：显式入口（搜索框 / ⌘K / 档案页跳入）可以跨状态改变选中；隐式动作（点星图上的点）不可以。**

理由：用户在搜索框里打出一个全名，意图已经明确是"我要看另一个节点"；而在星图上随手点一下，很可能只是想看看那是什么。前者值得改变状态机，后者不值得。

| 当前状态 | 搜索选中一个节点 |
|---|---|
| 总览 | → S0 选中它 |
| S0 选中 | → S0 选中它（换对象） |
| 场景态（S1/S2/S3） | → **先退出到 S0**，再选中它（不自动重问） |
| 多选态（S4/S5 凑家中） | → 与在该状态下点击一致：**加入集合** |
| 结果态（S4/S5 已查询） | → **先退回多选态**（掉聚焦、掉连线），再**加入集合**；需再按一次查询 |

代价说明：在 S1 里想"换个采购单位再问一次 S1"，需要 搜索 → 点 S1 两下。多一次点击，换来的是系统永远不猜用户想问什么。

可选缓解（建议做）：S0 面板上留一行**"再问一次：S1"**的快捷重放（只在上一次问过同类型场景时出现）。这样换对象后重问仍是一次点击，同时不破坏"选中≠提问"。

## 19. 已确认的视觉要求

1. **场景态的"不可点"必须被表达出来**（§17.2）：非答案节点光标为禁用态；悬停仍可看全名；星图上常驻轻提示"S1 结果 · 退出后可选其他节点"，退出按钮就在提示里。

3. 多选上限 4 家在界面上写明（计数 + 到数提示）。

## 24. 由"为什么只有它有颜色标记"引出的两个缺陷（2026-10-02）

项目方在 S4 画面里发现：一家供应商标签前有色点、线是青色，另一家没有、线是金色。
顺着这个问题查出两个真缺陷。

### 色点/线色的规则（先说清楚，这是设计而非 bug）

- **色点 = 主体标记**，只给"被放进对比篮的那几家"；答案节点永远没有色点。
- 主体的线用它的 slot 色；**不是主体的线用关系类型色**（中标金 / 采购冰蓝 / 供货铜 / 投标冷灰）。
- 所以截图里：有色点那家 = 你在对比的供应商；没色点那家 = 这次查询算出来的答案。
- slot 色按加入顺序分配：`#ff7a59 橙红 → #5ad1c8 青 → #b98cff 紫 → #f2e05c 黄绿`，**上限 4 家**（第 5 家就得换编码方式，不能再靠色相）。
- 同一套颜色同时出现在四处：星体的环、它的线、它标签前的点、信息栏矩阵那一列的表头点。

### 缺陷 1：主体配色泄漏到单主体场景

`slotIndex` 无条件按 `subjectIds` 填，于是 S1/S2/S3 里"连着唯一主体"的边也被涂成主体色——
而它的角色标签仍按关系类型上色，出现**同一条边线是橙色、标签写蓝色"采购"**的自相矛盾。
修法：只有 `displayMode === 'compared'` 才填 slot 表。

### 缺陷 2：`displayMode` 映射漏了 compared

ExploreView 的映射是 `picking → pool`，其余一律 `'scene'`，**`compared` 永远映射不到 `'compared'`**。
后果：对比态专属的东西（主体色环、色点、按主体着色）实际上从没生效过——
之前能看到色点，是因为 slotIndex 的填充时机在画边之后，误打误撞用上了"上一次"的表。

同时修掉填充时机：`slotIndex` 必须在画边**之前**填好。

### 验证

| 用例 | 带色点的标签数 | 期望 |
|---|---|---|
| S1（单主体） | 0 | 0（颜色继续表示关系类型） |
| S4（两家对比） | 2 | 2（两家各一色） |

控制台干净，`tsc` 0 错误。

## 25. 流光带停用 + 新增 S6 项目详情（2026-10-02）

### 25.1 状态机补全：关系数据只在"已提问"时产生

上一轮把两层曲线合并成一层时，只给"曲线+标签"加了门控，漏了两个关系渲染器：
**流光带**（只看 `bandEdgeList` 非空）和**中标金环**（只看"选中的是不是项目"）。
于是 `picked` / `picking` 状态下它们从侧门漏出去，表现为"选中节点周围自己亮了""进多选态线不熄""退出后金环还在"。

改法不是逐个补门控，而是**从源头断掉**：`applyEmphasis` 里"算底图 1.5 跳"那一整段删除，
关系数据只在 `scene / compared / s6` 三种状态下由 `sceneEdges` 提供。
金环机制整体删除（S6 用线色表达中标，不需要环）。

### 25.2 流光带：暂时停用，保留实现

`SHOW_FLOW_BANDS = false`（StarMap 顶部，带注释说明原因与恢复条件）。

停用的原因不是它不好看，而是它与曲线**各用一套配色**：曲线在对比态按来源主体上色，
带子永远按关系类型上色，同一批边叠两层，谁盖过谁取决于镜头远近——
边越少框得越近、带子相对越粗。所以才会出现"青岛云枢+哈尔滨众诚看着对、
换杭州天元+济南瑞康就全是金光"（前者 4 条边、后者 2 条边）。

**恢复条件**：接回来时必须与曲线共用同一套配色（对比态按主体、其余按角色），
并且只在"已提问"状态下出现。

### 25.3 新增 S6 · 项目详情

**点项目节点即进入 S6**（不是 S0 选中）。项目不是任何场景的主体，点它本身就是一个问题：
"这个项目是谁采购的、谁投了标、谁中了标"。

| 项 | 行为 |
|---|---|
| 触发 | 单击项目节点 / 深链 `?focus=proj:…` |
| 星图 | 聚焦该项目的参与方，三色曲线区分角色：采购冰蓝、中标金、投标冷灰（供货铜）；带角色标签 |
| 环 | **无**（改由线色表达） |
| 信息栏 | 按"采购方 → 中标方 → 投标方"的顺序列出名字，可点击把镜头移过去 |
| 锁定 | 与其他提问态一致：点别的星无效，Esc 或"退出这个问题"回到总览 |
| 数据 | 全部由图数据现算，**不需要后端新增场景** |

状态语示例：`S6 · 项目 山东省2025年度自然资源调查监测… · 包A · 采购 1 · 投标 3 · 中标 1`
