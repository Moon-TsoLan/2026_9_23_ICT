## 2. 一个技术澄清（给后端线，不影响前端契约）

你把「**FastAPI + SQLite**」当成一个整体排除了。这里得分清楚，否则可能选错技术栈：

| 组件 | 是不是并发瓶颈 | 说明 |
|---|---|---|
| **SQLite** | ⚠️ **是** | 单文件、**写操作串行加锁**，无法多实例横向扩展，多个 worker 同时写会 `database is locked`。**这才是你要排除的。** |
| **FastAPI** | ✅ **不是** | ASGI 异步框架，本身为高并发设计。配 `uvicorn workers` + Nginx/Gunicorn 即可多进程/多实例扩展，性能与 Django/Flask 同步方案不在一个量级。 |

**建议**（供后端线参考，我是前端视角，不越界）：

```
推荐：FastAPI  +  PostgreSQL / MySQL      —— 关系型主库，支持并发写、连接池、便于分页与聚合
可选：Neo4j                                —— 赛题明确推荐的知识图谱方案，用于任务二的关系查询
推荐组合：业务关系型库存明细(任务一结果) + Neo4j 存图(任务二关系) —— 各取所长
```

**关键点：无论后端最终选 PostgreSQL、MySQL 还是 Neo4j + 图查询，前端的接口契约完全不变**（第 8 节）。唯一受影响的是 `/api/scenes/{id}/query` 内部是 SQL join 还是 Cypher，那是后端的事。所以**前端现在就可以按契约开工**。

## 5. 星图「修逻辑」专项（重点）

**总原则：视觉参数一个都不动，只修数据流、执行位置、渲染批量、交互态。**

### 5.1 现状体检（问题清单，附证据）

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | `universe.ts:63` `bodies` / `:89` `links` | 数据硬编码 | 无法接真实数据 |
| 2 | `universe.ts:402` `placeStars()` | 180 步全对力导 + 36 步松弛，**同步**执行 | 节点上千时 O(n²)≈千万次运算，主线程冻结数秒 |
| 3 | `RelationView.vue:95` | 在 `onMounted` 里同步调 `placeStars()` | 首帧直接卡住 |
| 4 | `RelationView.vue:200–264` | **每个节点创建 4 个对象**（sprite+haze+pick+CSS2DObject） | 300 节点 = 1200 GL 对象 + 300 DOM，勉强；上万节点崩 |
| 5 | `RelationView.vue:284` `ensureLine` | **每条边一个 `THREE.Line`**，且每条边的标签是独立 CSS2DObject | 600 边 = 600 线 + 600 DOM 标签 |
| 6 | `RelationView.vue:481–518` | **每帧**对每条可见边重算 33 个贝塞尔点并上传 buffer | 每帧 600×33 次运算 + GPU 上传，掉帧主因 |
| 7 | `universe.ts:217/231/270/297/347` | `focusOf/roster/selection*` 把**业务语义**（谁和谁竞争/合作）写死在组件层 | 业务规则变了要改渲染代码 |
| 8 | `RelationView.vue:387` `cast()` | 每次 pointermove 对**全部** pick 做 raycast | 节点多时 hover 卡顿 |
| 9 | 无 LOD / 无采样 | 全量渲染 | 1000 公告的数据规模直接不可用 |

### 5.2 修法（分五层）

#### ① 数据层：星图不再自带数据

`StarMap.vue` 只吃 props，不知道业务：

```ts
// components/StarMap.vue  （只负责"画 + 交互"）
import type { GraphNode, GraphEdge } from '@/types/graph'

const props = withDefaults(defineProps<{
  nodes: GraphNode[]
  edges: GraphEdge[]
  placed?: Record<string, { x: number; y: number; z: number; scale: number }>  // 服务端给坐标则优先用
  focusId?: string | null
  highlightIds?: string[]      // 需要脉冲 + 排名徽标的节点
  ranks?: Record<string, number>   // id → 名次(1..N)，画徽标用
  dimOthers?: boolean          // true：非相关节点淡化到 18%（不是删除）
  reducedMotion?: boolean
}>(), { highlightIds: () => [], ranks: () => ({}), dimOthers: true })

const emit = defineEmits<{
  (e: 'select', id: string | null): void
  (e: 'hover', id: string | null): void
  (e: 'ready', firstFrameMs: number): void   // 用于页面显示"星图 X ms"
}>()
```

`universe.ts` 里的 `focusOf / roster / selectionGroups / selectionStats / selectionTitle / idleEdges` **全部删除**——它们回答的是"谁和谁有竞争合作关系"，属于**任务二关系建模**的职责，应由 `/api/scenes/*` 返回 `GraphNode[] + GraphEdge[]`。前端不再自己推关系。

> 这一步是"修逻辑"的核心：把**业务语义**从渲染层剥离出去。

#### ② 布局层：`useGraphLayout()` —— 三级降级

保留原有力导算法（它的参数调得不错），但改变**执行方式与时机**：

```ts
// composables/useGraphLayout.ts
export type LayoutStrategy = 'server' | 'worker' | 'inline-sample'

/** 三级策略，按优先级自动选择 */
export async function useGraphLayout(nodes, edges, opts): Promise<Placed[]> {
  // 1) server：后端随 SceneResult.graph 返回坐标（最佳，零前端开销）→ 直接用
  if (opts.placed) return fromServer(opts.placed)

  // 2) worker：节点数 > 200 时，把力导放 Web Worker，主线程不卡
  if (nodes.length > 200 && typeof Worker !== 'undefined') {
    return await runInWorker(nodes, edges)     // 原 placeStars 算法原样搬进 worker
  }

  // 3) inline-sample：小图（≤200）主线程直接算；大图先采样
  const sample = sampleTopWeight(nodes, 300)   // 全画采购单位 + 项目按金额前300 + 主体按频次前200
  return placeStars(sample, edgesOf(sample, edges))
}
```

**增量布局**：聚焦时新出现的节点**从邻域质心向外长出**，不重跑全量布局。这样点节点是"展开"，不是"重新洗牌"，空间记忆得以保留。

**采样规则（总览态）**：采购单位全画 + 项目按包金额取前 300 + 中标/投标/产品供应商按出现频次取前 200；其余以**点云尘埃**示意（`dust` 系统已有，直接复用），不可点、不参与布局。这样总览永远是几百个节点，而不是上万个。

#### ③ 渲染层：批量与 LOD

| 现状 | 改法 |
|---|---|
| 每节点 4 个对象 | ≤300 节点：维持现状（简单、可读）；>300：节点主体改 `InstancedMesh` 一次 draw call；`pick` 用单个 InstancedMesh + `instanceId` 反查 |
| 每条边 1 个 `THREE.Line` | **静态边合并成 1 个 `LineSegments` BufferGeometry**（一次性构建 + 只在布局变化时更新）；只有 `highlightIds` 相关的**少数边**保留独立曲线 + 流光动画 |
| 边标签 = 每条边一个 DOM | 只为 `focusId` 相邻的边创建标签，其余边不建 DOM |
| 节点标签 = 每个节点一个 DOM | 同屏标签上限 80 个，按"权重高/距离近"优先显示，其余隐藏（保留 sprite 光点） |
| 每帧重算全部边 | 每帧只更新流光边的顶点；静态边零帧开销 |

#### ④ 交互层：四态状态机

```ts
// ExploreView.vue 里的选中与场景状态
type ExploreState =
  | { kind: 'overview' }
  | { kind: 'focus'; id: string }
  | { kind: 'compare'; ids: string[] }   // S4/S5，2..N 个
  | { kind: 'detail'; id: string }       // 下钻到某条结果
```

| 态 | 触发 | StarMap props | NarrativePanel 内容 |
|---|---|---|---|
| overview | 进入页面 | `focusId: null`, `dimOthers: false` | 全局统计 + 场景提示 |
| focus | 搜索定位 / 点节点 | `focusId`, `highlightIds`, `dimOthers: true` | 主体画像 + 当前场景榜单 |
| compare | S4/S5 选 2..N 主体 | `focusId: null`, `highlightIds: ids` | 交集表（共同采购单位/项目） |
| detail | 点右侧一条结果 | 同上 + `highlightIds` 增补 | 下钻到 `CobDetail` |

**"闪烁 + 隐去"落实为**（对应 v1 第 6.4 节的三处修正）：

- **脉冲一次**：`highlightIds` 的节点播一次 600ms 环状扩散后静止 → 新增 1 个 `pulse` sprite（或环形 shader），**不逐帧改 DOM**。
- **排名徽标**：`ranks[id]` 有值时，节点旁挂一个 `#n` 小徽标（CSS2DObject，只对 ≤5 个节点创建）。
- **其余淡化**：`dimOthers` 时非相关节点 sprite/haze 的 opacity ×0.18，`alpha` 过渡 400ms；**不删除**（保留空间记忆），并在左下角常驻「重置视野」按钮。
- **无障碍**：`prefers-reduced-motion` 时脉冲/漂移/流光全关，改为静态高亮 + 徽标（原代码已部分处理，补齐脉冲与徽标）。

#### ⑤ 性能兜底：raycast 只在需要时做

`pointermove` 不再每帧全量射线检测：改为
- 只在 `pointermove` 且距上次检测 > 60ms 时做一次；
- pick 对象用**网格空间哈希**（cell ≈ 平均节点间距）先粗筛候选，再对候选做精确 raycast；
- 拖拽（`e.buttons`）时跳过。

### 5.3 星图视觉保留清单（明确不动）

✅ 保留：三种纹理（star/disc/cloud）与其 stops、`tint/innerOp/hazeOp/hazeMul` 全部参数、`FogExp2(0.007)`、`#0c0b0a` 背景、vignette 渐变、`star-label/star-edge` 字体与阴影、OrbitControls 手感参数、dust 星尘、呼吸/漂移曲线、合作=暖金/竞争=冷蓝的边色。

🚫 只新增（逻辑驱动）：脉冲环、排名徽标、淡化态、重置视野按钮。**这些是交互反馈，不改变整体气质。**

## 6. 三个新工作区 + 主体档案详细设计

### 6.1 数据接入 `IngestView.vue`（记录域）

**布局**：上下两段。上段「投递区」，下段「任务队列」。
**队列里每个任务卡** 三段式：文件树 → 流水线 → 汇总。

```
┌ 投递区 ───────────────────────────────────────────────┐
│  拖入一组数据（1 个公告 HTML + 同名附件 zip，可批量）      │
│  [选择文件]   已选 3 组 · 2 组已配对附件                   │
└──────────────────────────────────────────────────────┘
┌ 任务队列 ─────────────────────────────────────────────┐
│ ▸ t20260202_26140146   运行中  ●●●●○○○○○  4/9        │
│   ├ 公告 t20260202_26140146.html                      │
│   └ 附件 3 个 · PDF 86页 · XLSX · DOCX      [展开树]   │
│   ├ 读入公告 ✓  理解表格 ✓  抽候选 ⟳  …                │
│   └ 失败 1 · scanned_or_low_text_pdf → "附件疑似扫描件" │
│                                                       │
│ ▸ t20260202_26139731   完成   项目3 标的15 主体9        │
│   [去检索这批标的]  [去看这批关系]                       │
└──────────────────────────────────────────────────────┘
```

**要点**
- 公告与附件**成组**：按文件名前缀自动配对（`t20260202_26140146.html` ↔ `t20260202_26140146.zip`），允许手动改。
- **传输与处理分开计时**（赛题口径）：上传进度条 + 处理进度条是两个独立控件。
- 流水线步骤名直接用后端 `steps[].step`，前端维护中文映射表（第 8 节 `STEP_LABEL`）。
- 失败码 → 中文说明映射（`FAILURE_LABEL`），可展开看 `failure_message`。
- 重名公告：三选一「覆盖 / 跳过 / 存为新版本」，不静默覆盖。
- 完成后的两个出口按钮把 `announcement_id` 带进检索页/探索页（形成演示闭环）。

**组件**：`UploadDropzone` + `FileTree` + `RunPipeline` + `MetricCard`。

### 6.2 标的检索 `SearchView.vue`（记录域）

**布局**：顶部筛选栏（可折叠，已选条件以 chip 展示）→ 左「结果列表（虚拟滚动）」+ 右「详情卡」。移动端详情沉底。

**检索维度**（后端做过滤，前端只发条件）：

| 维度 | 控件 | 匹配字段 |
|---|---|---|
| 关键词 | 输入框（防抖 300ms） | object_name / project_name / brand / spec_model / 三主体名 |
| 中标供应商 | 主体选择器 | `subs[is_winner].supplier_name` |
| 产品供应商 | 主体选择器 | `cob.product_supplier` |
| 采购单位 | 主体选择器 | `project.purchaser` |
| 项目名称 | 输入 | `project_name` |
| 品目 | 目录树 A/B/C → 2022 目录 | `category_code/name/type` |
| 品牌 / 规格 | 输入 | `brand` / `spec_model` |
| 金额区间 | 双输入 + 确认（不实时查） | `unit_price` 或 `total_price`（口径可切） |
| 来源 | 复选 | `provenance.source_type` |

**列表列**（一屏 20 行，`CobTable`）：标的物名称 / 项目 / 采购单位 / 品目 / 品牌 / 产品供应商 / 规格 / 单价 / 数量 / 总价 / 中标供应商 / 来源。数字列右对齐 + `.num` 等宽。支持排序（金额/单价/相关度）。**表头吸顶**，行可键盘上下移动（无障碍）。

**详情卡**（`CobDetail`，检索页与探索页**复用**）：项目级 + 标的级 + 中标方 + 投标方 + 溯源，全部字段。空值统一显示灰色 `—`。

**导出**：`GET /api/objects/export?<同查询条件>` → 下载 CSV。这是**任务一"提取的数据表"提交物**的直接来源，要有按钮。

**性能**（对 <1s 红线）：服务端分页（keyset 分页，避免深 `OFFSET`）；首屏只请求 20 条；命中关键词在前端高亮（用 `mark` 标签，注意转义）。

### 6.3 关系探索 `ExploreView.vue`（宇宙域）★ 融合方案

**三段式布局**：

```
┌ 顶部：AppNav ────────────────────────────────────────────┐
├ 场景模板条 SceneBar（S1..S5 五个 chip，带当前选中态）────────┤
├────────────────────────────────┬────────────────────────┤
│                                │  叙事面板 NarrativePanel  │
│        StarMap（3D 星图）        │  ├ 主体标题 + 角色/地区     │
│   总览 / 聚焦 / 对比 / 详情       │  ├ MetricCard ×2~3       │
│                                │  ├ RankList（TOP5 横条榜） │
│                                │  └ [展开大图模式] [看明细]  │
├────────────────────────────────┴────────────────────────┤
│ 底部状态条：拖拽旋转 · 本次查询 412ms · [重置视野]            │
└──────────────────────────────────────────────────────────┘
```

- `SceneBar` 换场景 = 换"查询模板"（输入控件 + 输出结构），**不换页面**。
- `NarrativePanel` 按 `SceneResult.narrative` 渲染：`stats` → `MetricCard`；`ranking` → `RankList`；`table` → 表格；`combos`（S2）→ 共现条。
- **"数字先出、星图后补"**：拿到 `SceneResult` 后**先渲染叙事面板**（纯 DOM，几十毫秒），再用 `requestIdleCallback` 构建星图；星图未就绪时显示已有节点光点或骨架。因为"查询效率"计的是"结果完全渲染完毕"，而结果的核心是数字与清单。
- 底部状态条显示 `SceneResult.elapsed_ms` + 前端渲染耗时（既是验收工具，也是演示加分项）。
- **Compare 态用 3D 交集子图**（按你的决定，不降级 2D）：多个中心节点向交集节点发边，交集外的节点淡化。
- 需要多行明细时点「展开大图模式」：覆盖式浮层，**星图暂停渲染**（省性能），浮层内是完整表格 + 可选 ECharts。

**全局统计**：作为探索台内的一个「统计」标签（或独立轻量视图），用 ECharts 出分布图（品目/地区/年份）。**懒加载**，只在激活时 import。

### 6.4 五大场景模板（S1–S5 统一骨架）

**统一骨架**：`选镜头 → 填主体 → 展开关系 → 排序结果 → 图上定位 + 面板呈现`

| 场景 | 输入控件 | StarMap 表达 | NarrativePanel |
|---|---|---|---|
| **S1** 采购单位 → 长期/大量合作的中标供应商、产品供应商 | 1 个采购单位 | 采购方为恒星，合作方辐射 | 双指标榜（合作次数 / 交易总金额），可切排序 |
| **S2** 采购单位 → 高频投标主体 + 协同组合 | 1 个采购单位 | 采购方→项目→投标方 | TOP5 榜 + 协同组合共现条（A×B n 次） |
| **S3** 中标供应商 → 高频共同竞标主体 | 1 个中标供应商 | 该供应商为中心 | TOP5 榜 + 全部参与主体明细表 |
| **S4** 多中标供应商 → 共同合作的采购单位 | 2..N 个中标供应商 | 交集子图（多中心共指） | 采购单位交集表（频次/金额） |
| **S5** 多中标供应商 → 共同竞标的项目与结果 | 2..N 个中标供应商 | 交集项目子图 | 项目表（项目名/金额/各家是否中标） |

**实现方式**：五场景 = 五组配置（`scenes.ts` 里的 `SCENES: Record<SceneId, SceneMeta>`，含名称、主体选择器模式(单选/多选)、输出结构提示），**共用同一个渲染器与同一套 `SceneResult` 契约**。加场景 = 加配置，不改组件。这对"每个场景 4 分"最省事。

### 6.5 主体档案 `PartyView.vue`（记录域）

路由改为 `/party/:id`（原为 query `?id=`）。内容：主体名 + 角色 + 地区 + 指标卡（项目数/成交数/金额/同场次数）+ 关键事实列表 + 「在星图中查看」按钮（跳 `/explore?focus=<id>`）+ 「查看相关标的」按钮（跳 `/search`）。

### 6.6 导航与命令面板 `App.vue` / `AppNav.vue`

- 导航三项：**采集 / 检索 / 探索**（顺序即演示顺序）。主体档案是"点进去"的，不占导航。
- 全局 `⌘K` 命令面板：搜"页面 / 主体 / 项目"。**主体与项目的候选要来自后端接口**（原版是硬编码 `jumps` 数组）。
- **主题随路由自动切**：`/explore` → 宇宙域（深）；其余 → 记录域（浅）。切换用一次 `opacity` 过渡，不做花哨动画。

## 9. 性能红线落地清单（< 1 秒）

- [ ] 路由级懒加载：`three`、`echarts`、`vue-virtual-scroller` 均不在首屏包内。
- [ ] `vite.config.ts` 的 `manualChunks` 把 `three` 拆独立 chunk。
- [ ] 场景查询：**先渲染叙事面板（DOM），星图 `requestIdleCallback` 异步**。
- [ ] 检索：服务端 keyset 分页 + 前端虚拟滚动，绝不一次拉全表。
- [ ] 星图：总览采样（≤300 节点）、`server` 坐标优先、静态边合并、标签上限 80、raycast 节流 + 空间哈希。
- [ ] 布局：大图走 Web Worker；聚焦态增量布局，不重算。
- [ ] 上传：分片/并发受限；大文件给出预计时间。
- [ ] 骨架屏覆盖每个网络请求；错误态可重试。
- [ ] 右上角常驻「本次 xx ms」计时（数据来自 `elapsed_ms` + 前端渲染耗时）。

**验收方法**：Chrome DevTools → Performance 录制；Network 看请求数与时序；`vite build` 后看 chunk 体积；Lighthouse（`/search`）≥ 85。

## 11. 风险与坑点

| 风险 | 影响 | 对策 |
|---|---|---|
| 星图节点规模不可控 | 首帧卡死、掉帧 | 强制采样 + Worker 布局 + 增量展开；把"总览全量"这件事从产品上否掉 |

## 12. 一句话总结

- **除星图外全部重做**，按 `接入 / 检索 / 探索 / 档案` 四个工作区，配双域主题与设计令牌。
- **星图只修逻辑**：数据 props 化、布局下沉（server → worker → 采样）、静态边合并、标签 LOD、四态状态机、"脉冲一次 + 排名徽标 + 淡化不删除"。
- **五大场景 = 五组配置 + 一个渲染器**，统一 `SceneResult` 契约。
- **< 1 秒**靠"数字先出、星图后补"，外加全量懒加载与服务端分页。
