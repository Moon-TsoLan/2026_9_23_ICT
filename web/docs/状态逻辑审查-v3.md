# 探索页状态逻辑审查（对照《星图交互设计-v3》）

> 审查对象：`views/ExploreView.vue`、`components/SceneBar.vue`、`components/StarMap.vue`、`components/NarrativePanel.vue`
> 方式：静态读代码路径（未启动服务）。行号以 2026-10-01 17:39 版本为准。
> 结论：**15 处冲突，但只有 3 个根因。** 修根因，症状会一起消失。

## 一、三个根因

### 根因 A：没有"退出问题"这个动作

界面上只有"取消选中"（点空白 / Esc / 取消聚焦）和"回到全景"，**缺少"我不再问 S1 了"这个独立动作**。
于是"取消选中"被迫同时承担三件事：退聚焦、退场景、退镜头。它做不到，所以：

- 点空白 → 聚焦没了，但答案集还亮着（C1）
- 切场景 → 上一个问题的数据被 sceneView 挡掉，但 focusId 还指着旧答案（C10）
- Esc → 只退聚焦，用户以为退出了问题（C13）

**修法**：给"当前问题"一条与"当前选中"平行的生命周期。

| 动作 | 影响 |
|---|---|
| 取消选中（点空白 / Esc / ×） | 只动 `focusId` |
| **退出问题**（面板"当前问题"段的 × / 快捷键） | 清 `result`，星图回全亮、雾恢复呼吸 |
| 回到全景（顶栏） | 两者都做 + 镜头复位 |

### 根因 B："当前主体"有三份表示

| 表示 | 位置 | 谁在用 |
|---|---|---|
| `single`（字符串） | SceneBar.vue:36（子组件本地） | 单选场景输入框、`canQuery`、`run()` |
| `subjects`（数组） | ExploreView.vue:328 | 多选场景、对比篮、Shift+点 |
| `focusId`（节点 id） | ExploreView.vue:334 | 星图强调、接力、`onSceneChange` |

单选走 `single`、多选走 `subjects`、切场景走 `focusId`，三者互不知情，于是"篮子里有名字但查询按钮是灰的"这类现象必然出现。

**修法**：只留 `subjects: string[]`。单选场景=长度为 1 的数组；`single` 降级为输入缓冲，选定即写入 subjects；`canQuery` 统一为 `subjects.length >= (multi ? 2 : 1)`；`focusId` 只表示"正在看谁"，永不表示"要查谁"。

### 根因 C：底图和场景数据走了同一条通路

`absorbSceneNodes()`（ExploreView.vue:305）把场景里底图没有的节点并进 baseNodes。引用一变，StarMap 的 watch（:1373）触发 `rebuild()` → **536+ 节点全量重算力导** → 所有星体重新排位。

后果：同一家公司跨场景位置跳变；用户看到"图重新渲染"；推进式模型（指引 §10）的前提没了。

**修法**：布局结果按 id 缓存（`Map<id, Placed>`）。只有底图首次加载全量算；新节点用"已定位邻居质心 + 随机方向"落位，**老节点一律不动**。

## 三、建议的修复顺序

### 第 1 批：把"当前主体"收敛成一份（根因 B）

1. `subjects: string[]` 成为唯一真相；`single` 只当输入缓冲。
2. `canQuery = subjects.length >= (multi ? 2 : 1)`。
3. `emit('pick', scene, string[])`，删掉 `\u0000` 协议（C7）。
4. `pickScene` 不清 `subjects`，但输入框显示要与之一致（C2）。
5. 上限改成 4 并写在界面上（C6）。

**验收**：切场景后篮子与查询按钮状态一致；不再出现"有名字但按钮灰"。

### 第 2 批：把"选中"与"问题"拆成两条生命周期（根因 A）

1. 多选模式下**单击即加入**（C3）；Shift+点降级为"单选模式下也加入"。
2. 新增"退出问题"动作：清 `result` → 星图恢复全亮 + 雾恢复呼吸（C1、C1b、C13）。
3. `collectSubjectRelations` / `focusLocal` 在无场景时**回落到 baseEdges**（C8、C9）。
4. 点节点不再自动查询（C4）；若要保留便利，只在"类型匹配且该主体未查过"时自动查并在面板注明。
5. `onSceneChange` 时若 focusId 不属于新场景的合法主体，清掉聚焦（C10）。
6. 顶栏加一句话状态语（C11）。

**验收**：点空白真的回到总览观感；未提问时点任何节点面板上段都有内容；多选可用。

### 第 3 批：坐标缓存（根因 C）

1. `useGraphLayout` 增加 `Map<id, Placed>` 缓存与"只给新节点落位"的路径（C5）。
2. 底图首次加载才全量算。
3. 顺手修 C14、C15。

**验收**：连续查 S1→S2→S3，同一家公司在屏幕上的位置不动。

## 四、需要产品决策（不是 bug）

1. **点节点要不要自动跑当前场景？** 自动=便利但失去"我在问什么"的掌控；不自动=干净但多一步。折中见第 2 批第 4 条。
2. **默认态**：现在默认 S1；指引 §7 建议"未提问"。
3. **多选上限**：4 还是 8？影响 S4/S5 矩阵列数与交集命中率。
4. **对比篮放哪**：星图底部关注带（指引 §8）还是继续放右侧面板（现状）。
5. **S4/S5 边按来源主体着色**（指引 §4）目前完全没做——这是让"共同"在图上可见的关键，但 4 家=4 色会和三类节点色抢，需要先定配色策略。
