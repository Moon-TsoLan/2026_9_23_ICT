# 演示数据说明（ict_demo）

## 1. 数据规模

| 表 | 行数 |
|---|---:|
| announcement 公告 | 110 |
| project 项目 | 301 |
| cob 标的物 | 1007 |
| supplier 主体 | 241 |
| bid 投标记录 | 1551 |
| winner_coop_supplier 合作产品供应商 | 785 |

## 2. 数据构成

| 来源 | 公告数 | 说明 |
|---|---:|---|
| **真实**（`eval/gold/*.json` 黄金结果） | 10 | 人工核验过的真实抽取结果，`raw_json` 里没有 `_synthetic` 标记 |
| **合成**（结构化生成） | 100 | `raw_json` 含 `{"_synthetic": true, "seed": 20260928, ...}` |

合成数据不是随机灌的，按"能检验五大场景"的目标设计：

- **30 个采购单位**，覆盖医疗 / 教育 / 政务 / 自然资源 / 水利市政 5 个领域，分布在 20 个城市。
- 每个采购单位 **约 12 个项目**（3–4 篇公告 × 3 个包），保证 S1 / S2 有足够样本。
- 主体分三类，刻意制造三类关系信号：
  - **核心班子**：每个采购单位固定 4 家供应商，承担该单位 ~70% 项目的投标 → 制造**高频协同组合**（S2b、S3）。
  - **大厂对**：8 家"大厂"两两成对、跨采购单位出现 → 制造**跨单位交集**（S4、S5）。
  - **零散主体** 60 家，作为背景噪声，避免"人人都是高频"的假象。
- 标的物按领域取真实品目名（HIS 子系统、云桌面终端、GNSS 接收机…），带品牌与产品供应商，`category_type` 覆盖 A/B/C 三类。

> 随机种子固定为 `20260928`，同一份生成逻辑重跑结果一致。

## 3. 怎么和真实数据区分

```sql
-- 只看合成
SELECT * FROM announcement WHERE raw_json ? '_synthetic';
-- 只看真实（黄金）
SELECT * FROM announcement WHERE NOT (raw_json ? '_synthetic');
-- 只删合成数据（级联删除项目/标的/投标；孤儿主体一并清掉）
DELETE FROM announcement WHERE raw_json ? '_synthetic';
DELETE FROM supplier WHERE supplier_id NOT IN (SELECT supplier_id FROM bid);
```

## 4. 五大场景 · 推荐演示输入与实测结果

| 场景 | 推荐输入 | 实测结果 |
|---|---|---|
| **S1** 采购单位 → 合作的中标/产品供应商 | 采购单位 `北京市第二人民医院` | 返回 10 行：产品供应商「东软集团」8 次 / 1.40 亿；中标供应商「西安嘉和网络」4 次 / 9844 万 |
| **S2a** 采购单位 → 高频投标主体 TOP5 | 采购单位 `北京市第二人民医院` | 4 家并列 9 次投标（其中西安嘉和 9 投 4 中） |
| **S2b** 采购单位 → 协同投标组合 TOP5 | 采购单位 `北京市第二人民医院` | 核心班子两两组合 **各协同 9 次** |
| **S3** 中标供应商 → 共同竞标主体 TOP5 | 中标供应商 `青岛云枢云计算有限公司` | 最高「哈尔滨众诚工程」共同竞标 **11 次** / 3.70 亿 |
| **S4** 多中标商 → 共同合作的采购单位 | `广州神州电子有限公司,青岛云枢云计算有限公司` | 共同中标采购单位 **3 个**（全库最大交集；共 760 组主体对至少共享 1 个采购单位） |

组合查询（S4/S5）用**英文逗号**分隔全称，例如：

```bash
docker compose exec -T db psql -U ict -d ict_demo \
  -v kw='' -v purchaser='北京市第二人民医院' \
  -v winner='青岛云枢云计算有限公司' \
  -v suppliers='哈尔滨众诚工程有限公司,青岛云枢云计算有限公司' \
  < db/queries.sql
```

## 5. 已知限制

- **S4 的交集天然稀疏**：它要求两个主体在**同一个采购单位都拿过标**。当前全库 760 组主体对里有交集，但交集最多只有 3 个采购单位。够验证功能，但演示时排面不够满。
  → 如需 S4 出 6–8 行，可给生成逻辑加一条规则：**让"大厂对"在同一采购单位分别拿下不同包**。需要时再重灌。
- 合成主体的名称是"城市+字号+业务+有限公司"拼接而成，与真实企业重名的概率极低，但不代表真实存在。
- 合成公告没有真实项目编号（`source_project_no` 为随机串）。

## 6. 重灌方式

演示数据由一次性脚本生成后即删除（按约定**仓库内不留写入脚本**）。需要重灌或调整规模时，告诉我要改什么（项目数 / 采购单位数 / 主体规模 / 协同强度），我重新生成并覆盖。
