# 标络 · 采购公告实体挖掘与关系分析

项目说明更新于 **2026-10-16**，对应当前工作树。系统面向 ICT 赛题五，从采购公告及附件中提取采购单元、标的物和供应商，提供账号隔离的结果检索、官方三表 XLSX 导出及供应关系探索。

当前抽取契约为 **v1.3**，第8步合并规范为 **v10**，执行协议为 **delta-v5**。10月13日的官方格式兼容、10月14日的编号衔接修复和03探索修复均已实施；新版抽取尚未完成真实模型/OCR复测。旧版本测试成绩不能作为当前版本的准确率。

## 系统组成

| 层次 | 实现与责任 |
|---|---|
| 提取流程 | Python 多阶段流程；模型判断内容、采购单元归属及对象同一性，程序管理来源引用、结构校验、数值计算和审计 |
| 附件解析 | 原生文本读取与远端解析服务；复杂文档、扫描件沿既有转换/OCR链路处理 |
| 任务执行 | FastAPI接收上传并管理任务，独立工作进程执行抽取、入库；浏览已有结果不需要运行工作进程 |
| 数据存储 | PostgreSQL 16；公告、采购单元、标的、供应商与投标关系分别存储，完整成品和新增审计保存在公告 raw_json |
| 前端 | Vue 3、TypeScript、Vite；03探索使用 Three.js 呈现3D星图 |

公共结果采用 `announcement-v2`：**公告 → packages → cobs / subs**。一个图中的项目节点对应一个采购单元；公告、采购项目与采购单元不是同一个层次。字段含义统一定义在 `src/ict/fields.py`。

## 页面与功能

| 页面 | 当前功能 |
|---|---|
| 登录 `/login` | 基础用户名/密码注册、登录及退出；注册即建立空数据空间，业务页面需登录 |
| 01 上传 `/ingest` | 公告HTML与附件ZIP配对、上传、任务状态及15阶段进度；已完成公告可下载三表XLSX |
| 02 检索 `/search` | 标的检索、筛选、排序和分页；选中行查看右侧详情；按命中公告导出完整三表 |
| 03 探索 `/explore` | 主体搜索、按需补载、关系分页、主体档案、五类关系场景和多供应商对比 |
| 主体档案 `/party/:id` | 采购单位、供应商、项目及产品供应方相关信息；可明确跳转至星图定位主体 |

检索表格与详情按采购单元名称展示标段/合同包，金额显示万元两位。详情保留独立的品牌和产品供应商，并展示已有证据支持的供应商报价、成交金额、审查结论与未通过原因。旧记录没有的新字段保持未知，不因前端升级自动补齐。

03探索的五个场景分别是：采购单位的长期合作、高频投标，中标供应商的共同竞标，以及多中标供应商的交集采购单位、交集项目。项目选中后还可查看该采购单元的参与主体。

### 03探索的当前交互

- 默认底图保留采购单位和项目，高频供应商采样展示；搜索通过独立只读接口查找主体，目标不在底图中时先补载，再选中和定位。
- 底图与临时展示集合分开。普通补载按ID复用已有星体、拾取体和标签，不重新采样雾线或骨架；新增关系用于补载落位和当前问题展示。
- 关系支持分页，面板区分已加载数量和完整关联对象总数。项目参与名单直接查询数据库，不从默认采样名单推断。
- 对比篮按主体ID保存，最多4家中标供应商。加入前等待星体就绪；已选主体保留颜色环、优先标签及逐个定位、全部取景入口；查询没有交集也保留所选主体。
- 普通切页返回恢复底图、临时数据、对比篮、问题、图例、节点坐标和镜头。快照保存在应用内存；整页刷新重新建立会话，带focus参数的链接重新定位目标。
- 档案页明确“在星图中查看”时，新目标优先于旧问题；离页释放渲染资源、事件与轮询。切回仍需创建渲染资源，并非后台保留整套WebGL实例。
- 取消和操作代次拦截迟到回答；数据版本不一致返回409，保留原问题并提示刷新，不合入不同版本数据。

完整生命周期和接口约定见[03探索实施说明](doc/03探索按需补载与状态恢复-20261014.md)。

## 账号与赛题全量数据

注册不需要邮箱、短信、验证码或审批。账号使用服务端Cookie会话；检索、详情、下载、图谱、任务和runs均按当前账号隔离。登录/退出清空前端旧账号会话与星图内存，跨标签同步退出。

数据库复用公告tenant_id，只给project和supplier各增加一个tenant_id，新增账号和会话两表；其余明细通过项目关联隔离。同一公告可分别存在于不同账号，覆盖与轮次重排不影响其他账号。worker仍仅运行一个进程，扫描所有账号的任务。

已有全量数据在default空间时，服务器端创建赛题账号并绑定default，或将已注册但无数据/任务的账号绑定default；不需搬runs或重跑。普通注册不能自行认领历史数据。没有预置公共密码，密码交互设置。完整迁移和账号工具见[账号隔离与部署迁移](doc/账号隔离与部署迁移-20261015.md)。

## 官方格式与字段约定

导出文件包含 **总表、标的表、投标人表**，保留官方表名、原有列顺序和21个蓝色必需表头；标的表另加灰色列：单位、产品供应商、品目编码、品目ABC。

| 字段 | 当前约定 |
|---|---|
| UUID | 公告唯一标识 |
| 标段/合同包 | 区分标段、合同包、未分包和未知；标段显示原文标段名称，合同包显示包名称，明确未分包才显示“未分包” |
| 编号归属 | 原编号与内部引用分别保存；同号标段/合同包不按裸数字混并；缺号或同类型重号使用公告内身份 |
| 金额 | 抽取、入库及API仍使用元；展示、导出换算万元两位；XLSX按ROUND_HALF_UP舍入，空值与零区分 |
| 数量 | 数字；计量单位使用独立灰色列 |
| 供应商报价 | 最终投标/响应报价；供应商成交份额另存，不混作标的价格或包金额 |
| 审查 | 保留未通过供应商及原因，导出类别为“其他”；未知审查不由分数或中标身份推断 |
| 品目 | 当前目录匹配的最细有效名称；编码及ABC另列 |
| 品牌/产品供应商 | 原字段独立，产品供应商不回填品牌；品牌替代产品供应商仅用于03探索展示，不改写提取结果 |
| 规格型号 | 保留原文明示的定制、国标、按照招标要求提供等写法 |
| 多中标人 | 总表每个中标人一行；未披露个人成交份额时，不为每人重复整包金额 |

检索导出按命中的公告完整输出三表，无原5000行截断；也可单独导出一则公告。完整字段和流程衔接见[官方三表兼容说明](doc/官方三表兼容与流程衔接-20261013.md)。

## 提取流程

进度共15阶段：公告理解 → 表理解 → HTML抽取 → 统一采购单元归属 → 缺口规划 → 文件目检 → 原生证据复用 → 版面解析 → 页定位 → 附件抽取 → 归一化 → 合并 → 检查修复 → 产品供应方判断 → 落盘报告。

新增附件观测复用统一归属组件；COB合并使用来源引用和delta事务，SUB在包内合并身份、角色和字段来源。全过程保留原文、引用、接收错误、模型尝试及采用/否定记录。`08b_merge_evidence.json`为证据通道，不另算阶段。

附件流程的详细说明及历史实例见[附件解析与候选抽取实际流程](doc/附件解析与候选抽取实际流程-20261016.md)。需区分解析前的预算选页与解析后的模型页定位；解析服务会尝试合并跨页表，因此选中一个起始页记录时，抽取上下文可能已包含后续多页续表。可读PDF也可能继续走远端解析，不能概括为“可读即全文直送LLM”。

规则仍按[AGENTS.md](AGENTS.md)冻结；本次03探索改动只涉及只读查询、前端状态与渲染，没有修改提取规则、模型提示词、OCR、包归属或已暂缓的供应商缺口关闭逻辑。具体协议以[主路线契约](doc/主路线多步Agent设计契约.md)、[第8步规范](doc/第8步标的合并规范.md)为准。

## 本机启动与查看

在仓库根目录执行。已安装依赖的当前机器可直接启动；新设备先安装Python项目依赖、后端依赖并在 `web/` 执行 `npm ci`。

**已有数据库先停API/worker、备份并执行`db/002_accounts.sql`，再启动本版。** 新空卷会依次执行001/002；已有卷重启不会自动迁移。服务器按迁移说明创建或绑定赛题账号，本机首次使用也需注册/创建账号。

```powershell
# 数据库：持久化卷保留既有数据
docker compose up -d db
docker compose ps

# 后端：独立终端，读取根目录.env中的DATABASE_URL
$env:PYTHONPATH = Join-Path (Get-Location).Path 'src'
python -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

另开终端：

```powershell
cd web
npm run dev -- --host 127.0.0.1
```

前端地址：<http://127.0.0.1:5173/explore>。Vite将 `/api` 代理到后端8000；数据库容器为 `ict-pg`，本机端口 **15432**，容器内5432。本机使用 `.env.example` 建配置时须将其中旧的5432改为15432。密钥和真实连接配置放在本机 `.env`，不提交仓库。

未登录存活检查使用`/api/ping`；`/api/health`需要登录，并只返回当前账号的资料库计数及版本。

`DATABASE_URL`优先，换库后重启后端；不要只修改PGDATABASE而保留指向旧库的DATABASE_URL。仅检查已有数据时无需启动任务工作进程、模型服务、OCR或SSH隧道。任务处理和远端部署参数见[运行指南](eval/启动参数与运行指南.md)、[生产部署](deploy/生产部署.md)。
